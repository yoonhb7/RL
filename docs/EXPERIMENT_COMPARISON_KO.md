# 두 사거리 DQN에서 PedLink-DQN까지: 팀 프로젝트 설명서

작성 기준: 2026-11-11. 실행한 코드, 저장된 학습 메타데이터와 평가 결과를 기준으로 정리했다.

**기존 실험은 ‘두 사거리에서 차량 대기를 줄일 수 있는가’를 확인하는 중앙 DQN 기본 실험이다. 현재 실험은 ‘연속된 네 횡단보도에서 차량과 보행자의 대기를 어떻게 절충할 것인가’를 다루는 후속 실험이다.**

현재 실험의 프로젝트 이름은 **PedLink-DQN: 대기 연동 전환 비용을 적용한 4개 횡단보도 중앙 신호 제어**로 정한다. Pedestrian과 연결된 횡단보도를 뜻하는 프로젝트명이며, 학계에서 검증된 새 알고리즘 이름이나 신규성 주장이 아니다.

## 1. 처음 보는 팀원을 위한 요약

두 도로는 크기, 수요, 보상, 종료 시점이 다르다. 기존 실험의 차량 대기 12초와 현재 실험의 25초를 직접 비교해 알고리즘이 좋아졌다거나 나빠졌다고 말할 수 없다. 비교는 각 환경 내부에서 해야 한다.

현재 화면의 네 곳은 **네 개의 사거리**가 아니라 **한 도로 위 네 개의 신호 횡단보도**다. 네 개를 한 화면에 보여 달라는 요청을 반영한 구성이다.

### 현재 실험의 직접적인 출발점

**Poudel, Wang, Li, Zhu, Heaslip, _Joint Pedestrian and Vehicle Traffic Optimization in Urban Environments using Reinforcement Learning_, IROS 2025, arXiv:2504.05018v2.** [논문](https://arxiv.org/abs/2504.05018v2) · [저자 공개 코드](https://github.com/poudel-bibek/Urban-Control)

이 논문은 실제 Craver Road의 차량과 보행자 수요를 사용하고, 교차로 1개와 중간 횡단보도 7개를 단일 **PPO**로 제어한다. 핵심은 차량만 최적화하지 말고 보행자의 불편도 함께 다루자는 것이다. 원 논문의 대기열·최대 대기 기반 EI-MWAQ 보상, 큰 관측과 행동 공간, 실제 도로 및 수요를 현재 네 곳 실험과 동일하다고 설명하면 안 된다.

| 항목 | 원 논문 / 공개 코드의 문제 설정 | 현재 PedLink-DQN |
|---|---|---|
| 환경 | 약 750m 실제 간선 도로, 제어 노드 8개 | 약 320m 직접 생성한 합성 도로, 횡단보도 4개 |
| 알고리즘 | 정책과 가치 함수를 학습하는 PPO | 공동 행동의 Q값을 학습하는 vanilla DQN |
| 상태 | 10×96 형태의 큰 관측 | 대기·차량 수·현시 등의 요약 62차원 |
| 행동 | 교차로 4가지 × 횡단보도 2⁷ = 공동 조합 512개 | 네 횡단보도 각각 2가지, 공동 행동 16개 |
| 보상 | 대기열과 최대 대기 등을 사용하는 EI-MWAQ | 정지 누적 시간의 가중합과 선택적인 대기 연동 전환 비용 |
| 수요 | 실제 관측 기반 처리 수요 | 시드가 고정된 합성 도착 수요와 보행자 집중 유입 |
| 연구 의도 | 실제 도로에서 공동 최적화와 일반화 | 작은 도로에서 우선 규칙과 전환 비용의 효과를 분리해서 관찰 |

따라서 현재 실험은 **원 논문을 그대로 재현한 뒤 PPO만 DQN으로 교체한 공정 비교**가 아니다. PPO 논문의 문제의식을 바탕으로 만든 DQN 후속 설계다. 원 논문의 성능 개선 수치를 우리 결과로 인용해서는 안 된다.

구현 과정에는 `urban-ppo`에서 원 공개 환경을 실행한 단계, 같은 환경에 DQN을 붙인 단계, 단일 횡단보도로 축소한 단계가 있었다. 현재 비교 대상은 그 중간 8노드 실험이 아니라, 최신 **4개 횡단보도** 실험이다. 저자 코드 검토 기준 커밋은 `3dd10f46b599e56cc2bab93cda58cf414caa9511`이다.

## 3. 강화학습이 실제로 하는 일

SUMO가 차량 가속·감속, 차간 거리, 보행 이동과 정체를 계산한다. Python 제어기는 TraCI로 SUMO의 현재 상태를 읽고 신호를 바꾼다. DQN은 차량을 직접 운전하지 않으며, 신호 요청 조합을 선택한다.

| 개념 | 팀원이 이해할 설명 | 우리 구현 |
|---|---|---|
| 환경 | 행동에 따라 다음 상황과 점수를 돌려주는 세계 | SUMO 도로, 차량·보행자 수요, 신호 상태 기계 |
| 에이전트 | 어떤 행동을 할지 배우는 주체 | 도로 전체를 담당하는 신경망 하나 |
| 관측 s | 지금 상황을 숫자로 요약한 입력 | 차량 수, 대기열, 보행자 대기, 현시, 경과 시간 등 |
| 행동 a | 에이전트가 내리는 결정 | 여러 신호의 요청을 한 번에 묶은 공동 행동 |
| 보상 r | 그 행동 뒤 상황을 평가하는 점수 | 대기가 쌓이면 더 큰 음수, 대기가 적으면 0에 가까움 |
| 정책 | 상황에서 행동을 고르는 방식 | 허용된 행동 중 Q값이 가장 큰 행동 선택 |
| Q값 | 지금 행동한 뒤 미래까지 고려한 예상 점수 | MLP 출력 하나가 공동 행동 하나의 예상 할인 누적 보상 |
| 에피소드 | 한 번의 완결된 시뮬레이션 | 기존 900초, 현재 420초 |
| 탐험 | 아직 잘 모르는 행동도 시도함 | 학습 중 ε-greedy, ε가 1에서 0.05까지 감소 |
| 경험 재생 | 과거 경험을 섞어서 다시 학습함 | (s,a,r,s′,종료 여부,다음 행동 마스크)를 replay buffer에 저장 |
| 타깃 네트워크 | 학습 목표가 너무 빠르게 흔들리지 않게 함 | 250회 경사 업데이트마다 타깃 가중치를 동기화 |
| 행동 마스크 | 지금 허용되지 않는 신호 요청을 제외함 | 최소 녹색, 전환 중 상태, 보행자 우선 등의 제약 |

현재 모델의 MLP는 `62 → 128 ReLU → 128 ReLU → 16`이다. 기존 모델은 `29 → 128 ReLU → 128 ReLU → 4`다. 출력은 확률이 아니라 Q값이다. 둘 다 단일 에이전트, 모델 없는 가치 기반·오프폴리시 DQN이며, 저장된 실행은 vanilla DQN이다. PPO, 멀티에이전트, 그래프 신경망, Double/Dueling DQN을 현재 결과에 사용하지 않았다.

요약 관측은 SUMO의 모든 내부 상태와 미래 도착을 포함하지 않는다. MDP 형태로 설계했지만 완전한 Markov 상태를 관측한다고 보장하지 않으며, 부분 관측의 한계가 있다.

### 한 번의 학습 흐름

1. 수요 시드로 차량·보행자 도착 목록을 생성하고 SUMO를 초기화한다.
2. 현재 관측과 허용 행동 마스크를 읽는다.
3. ε 확률로 허용 행동 중 무작위 탐험을 하고, 그 외에는 허용 행동의 최대 Q값을 선택한다.
4. 신호 상태 기계가 요청을 처리한다. SUMO를 1초씩 총 5초 진행하면서 대기 시간을 적산한다.
5. 보상을 계산하고 다음 상태·다음 행동 마스크를 경험 재생에 넣는다.
6. 일정 간격마다 64개 경험을 무작위로 뽑아 Huber loss로 Q 네트워크를 학습한다.
7. 종료까지 반복하고 학습 기록·모델을 저장한다.

학습 목표는 `y = r + γ(1-done) max_{허용되는 a′} Q_target(s′,a′)`이고 γ는 0.99다. Adam 학습률은 0.001, replay 용량은 50,000, gradient clipping은 10이다. **탐험·평가 행동 선택뿐 아니라 다음 상태의 TD 타깃에도 마스크를 적용한다.**

`START_SIMULATION.cmd`로 보는 GUI는 이미 학습한 모델의 **추론 시연**이다. ε=0으로 신호를 고르며, 화면을 켜 두는 것만으로 가중치가 계속 학습되지는 않는다. 차량 생성·주행은 SUMO, 신호 판단은 DQN, 허용 여부와 황색·보행 정리는 상태 기계가 담당하므로 자동으로 움직여 보이는 것이다.

## 4. 기존 두 사거리 실험은 어떻게 구현했는가?

기존 코드의 핵심은 `src/traffic_rl/env.py`, `signals.py`, `dqn.py`이며, 실제 파일 구성은 저장소 `src/traffic_rl/`에서 확인할 수 있다.

도로는 직진 차량만 다니는 가상의 두 사거리다. 각 사거리는 동서/남북 녹색을 번갈아 사용한다. 5초마다 각각 유지(0) 또는 다음 현시(1)를 선택해 공동 행동 4개를 만든다. 기존 인코딩은 J0가 낮은 비트이고 J1이 다음 비트다.

29차원 관측은 전역 시간 1개와 사거리별 14개다. 사거리별로 유입 4개 차로의 차량 수·정지 차량 수 8개, 녹색 방향 one-hot 2개, 신호 단계 one-hot 3개, 경과 시간 1개를 사용한다. 정규화하고 범위를 제한한다.

최소 녹색 10초, 최대 녹색 60초, 황색 3초, 전적색 2초 제약을 둔다. 기존 실험에도 이미 기본 행동 마스크가 있다. 따라서 ‘행동 마스크를 처음 도입했다’는 것이 현재 실험의 새 아이디어는 아니다.

보상은 매 의사결정 구간의 `- 정지 차량·초 / 100`이다. 한 차량이 5초 멈추면 5 차량·초다. 모든 외부 차로를 합산하므로 신호 근처 일부 차로만 보고 다른 곳의 정체를 놓치는 것을 줄인다. 미진입 대기는 지표로 따로 기록하지만 이 기본 보상에는 직접 더하지 않는다.

수요는 동서 방향별 600대/시간, 각 사거리 남북 방향별 250대/시간을 기준으로 지수 분포 도착을 생성한다. 600초 동안 차량을 발생시키고 300초 더 배출하여 총 900초를 돌린다. seed별 명시적인 차량·경로 파일을 만들어 제어기끼리 같은 교통 수요를 사용한다.

얻으려던 것은 다음 세 가지다.

- SUMO↔TraCI↔DQN 학습·평가·GUI 연결이 실제로 동작하는 기준선.
- 단순한 네트워크에서 고정 신호와 대기행렬 기반 규칙보다 나아질 수 있는지의 확인.
- 후속 차량·보행자 문제에 재사용할 DQN, 모델 저장, 수요 고정과 평가 기반.

## 5. PedLink-DQN은 어떻게 구현했는가?

### 도로와 관측

차량은 왕복 각 1차로를 따라 C1~C4를 연속해서 지난다. 보행자는 배정된 횡단보도 한 곳에서만 건넌다. 차량 최고 속도는 약 40km/h, 보행자 최대 속도는 1.3m/s다. 이 환경은 직접 생성한 합성 도로이며 실제 Craver Road 지도를 잘라 낸 것이 아니다.

관측 62개는 `전역 시간 1 + 횡단보도별 15×4 + 미진입 차량 수 1`이다. 각 곳의 15개는 다음과 같다.

| 관측 항목 | 개수 |
|---|---:|
| 양방향 정지 차량 수 / 전체 차량 수 | 2 + 2 |
| 양쪽 보행자 대기열 | 2 |
| 가장 오래 기다리는 보행자 / 차량의 대기 | 1 + 1 |
| 횡단 중인 보행자 수 | 1 |
| 현재 신호 단계 경과 시간 | 1 |
| 차량·황색·전적색·보행·보행 정리 단계 one-hot | 5 |

입력마다 차량 수·시간의 단위 차이를 줄이도록 정규화하고 [0,2]로 제한한다. 보행자 수, 보행 대기, 횡단 점유를 명시적으로 읽는 점이 차량만 보던 기존 실험과 크게 다르다.

### 공동 행동과 신호 상태 기계

각 곳은 차량 서비스 요청 0, 보행 서비스 요청 1이다. 네 곳의 조합이 `2⁴=16`개다. 현재 코드는 `[C1,C2,C3,C4]` 순서의 사전식 조합을 사용한다. 예를 들어 행동 ID 5는 `[0,1,0,1]`, 즉 C2와 C4에 보행 요청, C1과 C3에 차량 요청이다. 기존 두 사거리의 비트 순서와 혼동하지 않는다.

요청 즉시 위험하게 녹색이 뒤집히는 구조가 아니다. 공통 상태 기계가 아래 순서를 처리한다.

`차량 녹색 → 황색 4초 → 전적색 1초 → 보행 녹색 → 보행 정리 최소 10초 → 차량 녹색`

최소 차량 녹색 15초, 최소 보행 녹색 10초를 지킨다. 보행자가 기다리면 차량 녹색 60초 이후에는 보행 요청을 강제하고, 차량이 기다리면 보행 녹색 30초 이후 차량 요청을 강제한다. 횡단 중인 사람이 남아 있으면 정리 시간이 지나도 차량 녹색으로 돌아가지 않는다. 이 공통 제약은 세 변형 모두 같다.

이 제약들은 시뮬레이션의 충돌 방지 설계다. 실제 도로 신호 기준 인증이나 현실에서의 안전 보장을 의미하지 않는다.

### 현재 보상

5초 구간에서 `V=정지 차량·초`, `U=미진입 차량·초`, `P=정지 보행자·초`라 하면:

`r_base = -(V + U + 2P) / 100`

보행자 가중치는 2다. 모두를 똑같이 처리했다는 의미가 아니라 보행 대기를 상대적으로 더 중요하게 둔 설계 선택이다. 미진입 대기를 포함해 차량을 네트워크 밖에 대기시키는 것을 공짜로 취급하지 않게 했다.

현재 기록하는 대기는 누적 정지 시간이다. 보행 우선 기준의 ‘30초’는 현재 대기열에서 가장 오래 **연속 대기한** 사람의 시간이다. 결과의 개인별 누적 대기, P95, 순간 최장 연속 대기는 서로 다른 지표다.

## 6. 우리가 추가한 아이디어와 구현 상태

세 변형은 같은 도로·관측·행동·학습 예산을 사용한다. `adaptive`라는 내부 이름은 여기서 대기 연동 전환 비용 변형을 뜻한다.

| 변형 | 코드에 있는 차이 | 실험에서 확인하려는 것 |
|---|---|---|
| `basic` 기본 DQN | 공통 신호 제약 + 기본 보상 | 차량·보행 가중 보상만으로 어떤 정책이 나오는가? |
| `priority` 보행자 우선 DQN | 기본형 + 보행 최장 대기 30초 이상이면 허용 행동을 보행 요청으로 제한 | 긴 보행 대기 꼬리를 줄일 수 있는가? 차량 지연은 얼마나 늘어나는가? |
| `adaptive` 대기 연동 비용 DQN | 우선형 + 보행 대기에 따라 약해지는 전환 비용 | 불필요한 전환 억제와 보행 서비스 사이의 절충이 가능한가? |

### 아이디어 A: 보행자 대기 기반 우선 마스크

차량 녹색 중 최소 15초가 지났고 최장 보행 대기가 30초 이상이면 해당 곳에는 보행 요청만 허용한다. DQN이 제약을 위반한 행동을 골랐다가 사후에 덮어쓰는 방식이 아니라, 학습과 추론에서 허용 행동 집합 자체를 제한한다. 이미 전환 중인 상태는 공통 상태 기계를 따른다.

**30초 이내 횡단 시작을 엄밀히 보장하는 규칙은 아니다.** 의사결정 간격 5초, 황색·전적색, 기존 단계 제약 때문에 실제 대기는 30초를 넘을 수 있다. 우리가 검증한 것은 규칙 적용과 관측된 대기 분포다.

### 아이디어 B: 보행자 대기에 연동한 전환 비용

각 횡단보도 i에서 현재 최장 보행 대기를 wᵢ라고 하면:

`cᵢ = 0.02 × I(서비스 요청 전환 발생) × max(0, 1 - wᵢ/30)`

`C = (c₁+c₂+c₃+c₄)/4`, `r_adaptive = r_base - C`

보행 대기가 짧으면 신호를 바꿀 때 비용을 주고, 대기가 길수록 비용을 줄이며, 30초 이상이면 비용이 0이다. 무조건 전환을 아끼다가 보행자를 계속 기다리게 하는 부작용을 줄이려는 설계다. 비용은 차량↔보행 서비스 요청이 바뀔 때 부과하고, 황색·전적색 등 중간 단계마다 중복 부과하지 않는다. 현재는 양쪽 전환 모두 보행 대기로 비용을 조절한다.

0.02는 보상에 직접 더해지는 무차원 계수이며 한 번 전환이 0.02초라는 뜻이 아니다. 네 곳을 평균하므로 보행 대기가 0일 때 한 곳만 전환하면 전역 비용은 0.005, 네 곳 모두 전환하면 최대 0.02다. 이 값과 30초 임계값은 초기 실험용 선택값으로, 체계적 탐색으로 최적이라고 확인한 값이 아니다.

이 두 아이디어는 **구현하고 각 조건을 따로 학습·평가했다.** 다만 보행자 고려, 행동 마스크, 보상 가중치, 전환 페널티 각각이 기존 연구에 없는 최초의 개념이라고 주장하지 않는다. 우리 기여 후보는 특정 문제에서 이 규칙과 비용의 조합을 정의하고 효과·한계를 분리해 검증하는 것이다.

| 현재 수요 유형 | 양방향 각각 차량 수요 | 횡단보도별 보행 수요 | 추가 사건 |

표의 시간당 값은 도착 생성률이다. 실제 300초 동안 생성된 개수는 시드에 따라 달라진다. 모든 방법에 동일한 명시적 수요 파일을 사용하며 해시 일치로 확인한다.

현재는 원 논문의 PPO와 동일한 조건·예산으로 비교하지 않았다. 같은 GPU에서 돌아간다는 사실이나 DQN/PPO라는 이름만으로 우열을 정할 수 없다. 작은 MLP의 현재 코드는 CPU를 사용하므로 RTX 5080이 있어도 자동 GPU 학습이 되지 않는다.

## 8. 실제로 얻은 결과

### 기존 두 사거리: 100회 학습 모델

평가 시드 5개의 평균이며 ±는 시드 간 표준편차다.

| 제어기 | 도착 차량 평균 대기(초) | 평균 도착 차량 수 | 미도착 / 미진입 |
|---|---:|---:|---:|
| 고정 신호 | 27.24 ± 0.58 | 363.8 | 0 / 0 |
| 대기행렬 규칙 | 15.26 ± 1.89 | 363.8 | 0 / 0 |
| DQN | 12.02 ± 1.36 | 363.8 | 0 / 0 |

DQN은 이 평가에서 고정 신호 대비 약 55.9%, 대기행렬 규칙 대비 약 21.2% 낮은 평균 대기를 보였다. `queue`는 직접 만든 간단한 대기행렬 규칙이며 현장 감응식 신호 전체를 대표하지 않는다. 첫 실행에서 공유된 20회 학습 결과와 여기의 100회 학습 결과를 혼동하지 않는다.

### PedLink-DQN: 조건별 30회 학습 모델

각 행은 평가 시드 3개의 지표를 같은 비중으로 평균했다. 보행 P95는 세 시드 각각의 95백분위수를 평균한 값이지, 모든 사람을 합쳐 다시 계산한 P95가 아니다. 전환은 네 곳의 서비스 요청 전환 합계다.

| 수요 | 방법 | 차량 평균 대기(초) | 보행 평균 대기(초) | 보행 P95(초) | 전환 수 |
|---|---|---:|---:|---:|---:|
| 균형 | basic | 13.92 | 21.87 | 54.40 | 42.67 |
| 균형 | priority | 32.66 | 15.08 | 35.57 | 47.33 |
| 균형 | adaptive | 25.45 | 15.21 | 34.55 | 52.33 |
| 차량 집중 | basic | 20.23 | 20.61 | 50.18 | 40.33 |
| 차량 집중 | priority | 18.23 | 16.67 | 36.98 | 32.67 |
| 차량 집중 | adaptive | 27.04 | 16.01 | 37.80 | 40.00 |
| 보행 집중 | basic | 12.70 | 9.87 | 33.02 | 33.67 |
| 보행 집중 | priority | 16.65 | 9.64 | 31.93 | 34.67 |
| 보행 집중 | adaptive | 19.41 | 12.23 | 29.13 | 46.00 |

해석은 다음과 같다.

- 보행자 우선 규칙은 이번 평가의 모든 수요 유형에서 기본형보다 보행 P95가 낮았다. 균형 수요에서는 차량 대기가 크게 늘어 절충이 드러났다.
- 대기 연동 비용을 더한 변형도 기본형보다 보행 P95는 낮았지만, 우선 규칙만 쓴 것보다 항상 좋지는 않았다. 차량 집중에서는 우선형보다 차량 대기와 보행 P95가 모두 높았다.
- **전환 비용을 넣었는데도 이번 adaptive 모델의 전환 수는 세 수요 모두 priority보다 많았다.** ‘비용으로 실제 전환을 줄였다’는 결론을 현재 결과로 뒷받침할 수 없다. 짧은 학습, 비용 크기, 보상과의 상호작용을 더 확인해야 한다.
- 보행 집중에서는 adaptive의 P95는 개선됐지만 보행 평균 대기는 악화됐다. 평균과 긴 대기 꼬리는 같은 목표가 아니다.

27회 평가 중 충돌·teleport 집계는 모두 0이었다. teleport는 비활성화했다. 다만 종료 시 다음 네 실행에 차량이 남았다: `basic/vehicle-heavy/1001` 1대, `basic/vehicle-heavy/1002` 5대, `priority/balanced/1003` 2대, `adaptive/vehicle-heavy/1001` 5대. 합계 13대이며 미진입 차량, 잔여·미진입 보행자는 모두 0이었다.

현재 대기 지표는 종료 시점까지 관측한 출발 개체별 정지 누적 시간이고, 남은 차량은 이후 대기가 반영되지 않는 **중도 절단**이 있다. 전원이 도착한 결과와 동등하게 취급하지 않는다. 후속 평가에서는 충분한 배출 시간과 완료율을 함께 보고해야 한다.

검증 기록은 27회 수요 일치, 차량·보행 인원 회계, 45,360개 신호 노드·초의 단계/정리 조건을 확인했다. GUI 시연도 동일 조건의 headless 결과·행동 기록과 일치했다. 영상은 실제 SUMO GUI의 50개 프레임으로 만든 것이며, 별도의 그림 애니메이션이 아니다.

## 9. 지금 말할 수 있는 것과 아직 필요한 것

**확인한 것:** SUMO-DQN 학습과 추론이 실제로 동작한다. 보행 우선 마스크와 대기 연동 전환 비용이 구현돼 있고 각각 따로 학습했다. 보행 지연의 꼬리와 차량 지연 사이의 절충이 관찰된다.

**아직 확인하지 않은 것:** 일반적으로 DQN이 PPO보다 우수한지, 비용이 전환을 안정적으로 줄이는지, 여러 초기화에서도 효과가 유지되는지, 실제 도로에서도 통하는지, 방법이 문헌 전체에 대해 새로운지.

가벼운 논문·보고서로 발전시킬 때의 연구 질문은 **‘보행자 대기 제약을 적용한 중앙 DQN에서 대기 연동 전환 비용은 차량 효율과 보행 지연 분포에 어떤 영향을 주는가?’**로 잡을 수 있다. 결과에 맞춰 연구 질문을 검증해야 하며 개선된 조건만 골라 제시해서는 안 된다.

권장 후속 실험은 다음 순서다.

1. 세 변형에 고정 신호와 보행 대기 기반 규칙 제어기를 추가한다. 현재 네 곳 결과에는 이 두 기준선이 없다.
2. 더 긴 배출 또는 공통 종료 정책으로 잔여 차량 편향을 줄이고 완료율·누적 비용을 함께 보고한다.
3. 독립 학습 초기화 최소 5개와 더 많은 공통 평가 수요 시드로 평균·변동성·대응 비교를 확인한다. 현재 수요 시드 3개는 학습 초기화 3개가 아니다.
4. 대기 임계값과 비용 계수, 보행 가중치, 학습량을 분리해 실험한다. 보행 우선 없이 비용만 넣는 변형, 고정 전환 비용 변형도 더하면 기여 분리가 명확해진다.
5. PPO와 비교할 경우 같은 네 곳 환경·보상·제약·평가 수요와 충분한 학습 예산을 사용한다. 원 논문의 결과표를 다른 환경의 DQN 결과와 직접 비교하지 않는다.

## 10. 팀이 코드를 읽고 실행하는 방법

GitHub 저장소: [yoonhb7/RL](https://github.com/yoonhb7/RL)

| 브랜치 | 목적 |
|---|---|
| `main` | 두 실험의 안내·비교와 최신 배포 파일 |
| `experiment/corridor2-dqn` | 기존 차량 중심 두 사거리 DQN 기준선 보존 |
| `experiment/pedlink-dqn` | 현재 네 횡단보도 DQN, 세 변형의 모델·결과·실제 GUI 시연 |

기존 실험은 저장소 최상위의 `run.py`, `START_SIMULATION.cmd`, `src/traffic_rl/`, `sumo/corridor2/`, `models/corridor2-100ep/`, `reports/corridor2-100ep/`를 읽는다.

현재 실험은 `experiments/pedlink-dqn/`에서 읽는다. `run.py`가 네 곳의 도로·수요·관측·행동을 정의하고, `core.py`가 공통 신호 상태 기계와 학습·평가 및 대기 집계를 맡는다. 신경망·replay·마스킹 TD 타깃은 최상위 `src/traffic_rl/dqn.py`를 공유한다. 원 작업 폴더의 sibling 프로젝트를 가져오지 않도록 배포 구조를 정리했다.

새 PC에서는 저장소 최상위에서 가상환경을 만들고 의존성을 설치한다. GUI는 전체 SUMO 설치의 `SUMO_HOME`을 설정한다. RTX 5080용 PyTorch/CUDA 선택은 해당 PC에서 확인하되, 현재 제공 모델·코드는 CPU 실행이 기준이다.

```powershell
git clone https://github.com/yoonhb7/RL.git
cd RL
git switch experiment/pedlink-dqn
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# 설치 경로에 맞춰 변경
$env:SUMO_HOME = 'C:\Program Files (x86)\Eclipse\Sumo'

# 현재 저장된 adaptive 모델 평가: 기존 결과를 덮어쓰지 않는 새 출력 폴더
.\.venv\Scripts\python.exe experiments/pedlink-dqn/run.py evaluate --model experiments/pedlink-dqn/results/train-adaptive/model.pt --out results/local/pedlink-evaluation-1

# 실제 SUMO GUI
.\experiments\pedlink-dqn\START_SIMULATION.cmd

# 세 변형을 새로 학습하고 평가한 뒤 GUI: 기본 각 30회
powershell -ExecutionPolicy Bypass -File .\experiments\pedlink-dqn\RUN_HERE.ps1 -Mode All -Episodes 30
```

모든 출력 폴더는 새 이름을 사용한다. 현재 체크포인트는 추론용 가중치·환경 스키마·메타데이터를 담으며 replay와 optimizer를 보존한 완전한 중간 재개 파일이 아니다. 더 긴 학습은 `--episodes`를 지정해 새 실행으로 시작한다. 두 실험의 모델은 관측·행동·신호 구성이 달라 교환해서 사용할 수 없다.
