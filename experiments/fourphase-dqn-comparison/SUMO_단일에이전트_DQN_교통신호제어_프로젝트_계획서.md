# SUMO 가상 연속 교차로의 중앙집중형 DQN 교통신호 제어 계획서

> 버전 v0.2 · 2026-11-12
>
> 주 실험: 직접 설계한 가상 교차로 2개. 선택 사례: 세종대 OSM 도로망.
>
> 진행 원칙: 도로·집계 확인 → 기준선 → 중앙 DQN → 동일 조건 평가 → 필요한 대조 실험.

## 1. 연구 목표와 범위

가상 연속 교차로 2개를 하나의 DQN으로 제어하고, 같은 차량 출발 목록과 신호 제약에서
고정신호·대기행렬 규칙 대비 정지 차량-초, 대기시간, 처리량이 어떻게 달라지는지 평가한다.
주제는 강화학습 제어 성능을 확인하는 시뮬레이션 연구이며 현장 방문·교통량 계수·촬영은 하지 않는다.

세종대 실제 지도를 사용하는 일은 필수 선행 단계에서 제외한다.
기존 OSM 입력·실패 기록·수정본 결과는 선택 확장 사례로 보존한다.
실제 신호 운영·교통 수요를 보정하거나 현장 배치 효과를 검증했다고 주장하지 않는다.
이전의 실제 도로 중심 계획은 [이전 계획 보관본](docs/archive/plan_before_synthetic_corridor.md)에 있다.
보관본의 현장 조사 요구와 실행 순서는 현재 계획에 적용하지 않는다.

연구 질문은 다음과 같다.

- **RQ1, 필수:** 중앙 DQN이 같은 조건의 고정신호·대기행렬 규칙과 비교해 어떤 성능을 보이는가?
- **RQ2, 필수:** 저·균형·고수요, 방향 불균형, 도중 수요 변화에서 성능 차이는 어떻게 달라지는가?
- **RQ3, 권장:** 학습하지 않은 출발 목록과 서로 다른 학습 시드에서 결과가 얼마나 일관적인가?
- **RQ4, 선택:** 인접 교차로 상태, 행동 설계 또는 보상을 한 가지 바꾸면 어떤 효과가 생기는가?

중앙집중형 다중 교차로 제어 자체를 새로운 알고리즘이라고 주장하지 않는다.
기본 결과를 얻은 뒤 필요하면 비교 가능한 대조 실험 하나를 추가한다.

## 4. 주 실험의 환경과 MDP

교차로 A와 B는 동서 방향으로 350m 떨어져 있고 각 경계 도로는 250m다.
방향당 1차로, 직진 전용, 제한속도 13.89m/s로 시작한다.
서·동쪽 차량은 두 교차로를 연속 통과하며 북·남쪽 차량은 해당 교차로를 통과한다.
두 교차로의 상호 영향을 확인하면서 회전·보행·차로 변경 변수를 줄이는 설계다.

| 요소 | 현재 정의 |
|---|---|
| State | 교차로별 현시 6 + 현시 경과시간 1 + 방향별 대기행렬 4 + 방향별 차량 수 4, 두 교차로 30개 + 남은 시간 = 31개 |
| Action | 0: A/B 유지, 1: A만 전환 요청, 2: B만 전환 요청, 3: A/B 전환 요청 |
| Reward | 매 행동의 5초간 전체 네트워크 정지 차량-초의 음수. 내부 차로 포함 |
| 전환 제약 | 최소 녹색 10초, 최대 60초, 황색 3초, 전적색 1초. 안전 제어기가 강제 |
| Episode | 0–1200초, Warm-up 120초 후 제어 216회. 출발은 900초까지, 이후 잔여 차량 처리 |
| 알고리즘 | Gymnasium 사용자 환경 + SB3 vanilla DQN, 신경망 31→64→64→4 |

전환 요청이 거부되더라도 5초는 진행하며 요청 행동·적용 여부를 함께 기록한다.
별도의 학습 Action Mask나 Double/Dueling/PER는 현재 구현하지 않는다.
관측은 [0,1]로 정규화하고 원시 수치는 로그에 남긴다. 정규화 상한을 넘는 정보 손실은 한계로 기록한다.

## 5. 수요·기준선·평가 설계

기본 수요는 low, balanced, high, unbalanced, changing의 다섯 종류다.
changing은 450초에 동서 유입 비율을 뒤집는다. 출발 목록은 시드로 생성한 뒤 파일에 고정한다.
유입률 상세와 실제 명령은 [실행 안내](docs/corridor2.md)에 있다.

| 비교 대상 | 내용 |
|---|---|
| Fixed-time | 각 녹색 30초, 주기 68초, A Offset 0초·B 25초. 단순 가정 기준선 |
| Queue rule | 반대 축의 대기 차량이 2대 초과 많으면 전환 요청. DQN과 같은 안전 제약 |
| Central DQN | 공동 관측 31개로 공동 행동 4개 선택. 평가에서는 탐색 없음 |

고정신호 30초·Offset 25초는 검증 수요로 최적화한 값이 아니다.
따라서 이 기준선과의 차이를 최적 고정신호 대비 개선으로 표현하지 않는다.
최종 비교를 강화할 때는 **검증 수요만으로** 고정신호 녹색시간·Offset을 고르는 실험을 추가한다.
Queue rule은 자체 규칙이며 SUMO 내장 actuated 또는 논문의 Webster 기준선과 동일하지 않다.

학습 수요 시드 100–109, 검증 1000–1002, 테스트 2000–2004를 분리한다.
검증 보상으로 모델을 선택하고 테스트는 최종 평가에만 사용한다.
기본 실험은 다섯 수요를 학습에도 사용하므로 새 수요 유형에 대한 일반화로 해석하지 않는다.
그 질문은 특정 유형을 학습·검증에서 제외한 별도 실험으로 다룬다.

동일 수요·동일 SUMO 시드로 세 방법을 비교하며 입력 사본·SHA-256을 보관한다.
독립 학습 시드 42/43/44로 같은 예산을 반복하고, 수요 시드 간 변동과 학습 시드 간 변동을 구분한다.
초기 예산은 실행당 50,000회 행동이다. 충분한 학습량인지는 학습·검증 곡선을 보고 검토하며 성능을 미리 보장하지 않는다.

필수 지표는 전체 정지 차량-초, 관측 집단 평균 대기시간, 이동시간, 도착·미완료·미진입 차량 수다.
평균은 출발 예정시각으로 정한 같은 차량 집단을 사용하고 미완료 차량의 관측 대기도 포함한다.
미진입 대기는 별도로 보고한다. 비교 집단이 모두 완료되지 않으면 대기시간 감소율을 산출하지 않는다.
모든 실행에서 충돌·텔레포트 0, 차량 집계 일치, 신호 순서·시간·색상 검사 통과를 요구한다.

## 6. 진행 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1, 지금 | 가상 도로 생성·모의 연결 검사·balanced 검증 수요 1개 fixed/queue 실행 | 도로 생성 성공, 집계·신호 검사 통과, 충돌·텔레포트 0. 잔여 차량 기록 |
| 2 | Mac에서 A/B 차량·신호 및 수동 행동 확인 | 공동 행동은 같은 5초 진행, 최소 녹색·황색·전적색 보존, reset으로 같은 창 재시작 |
| 3 | 5,000회 짧은 DQN 학습 | 모델·Replay 학습·Target 복사·검증 로그 정상 생성 |
| 4 | 동일 예산으로 독립 학습 시드 3개 이상 | 입력·하이퍼파라미터·체크포인트 보존 |
| 5 | 고정된 테스트 수요로 세 방법 평가 | 평균·변동·완료율·안전 검사를 함께 보고 |
| 6, 선택 | 관측/행동/보상 한 가지 대조 실험 또는 세종대 전이 | 기본 실험과 동일 조건을 유지하고 바꾼 변수 명시 |

짧은 학습이나 단일 시드 성능만으로 최종 결론을 내리지 않는다.
주 실험의 도로 생성·학습·평가는 원격 Linux의 화면 없는 SUMO에서 실행한다.
Mac SUMO GUI는 시각 확인에 사용하며 Python은 서버에서 TraCI로 연결한다.
사용자가 터미널에서 직접 실행한다. 문서·코드 수정만으로 실행 완료라고 기록하지 않는다.

## 7. 파일과 다음 명령

- 환경 설정: `configs/corridor2.json`, 학습 설정: `configs/corridor2_dqn.json`.
- 도로 생성: `scripts/build_corridor2.py`, 환경: `src/envs/corridor_env.py`.
- 학습: `scripts/train_corridor2_dqn.py`, 평가: `scripts/evaluate_corridor2.py`.
- Mac 확인: `scripts/view_corridor2.py`, GUI 규칙 수정: `src/traffic/corridor_controller.py`.
- 실행 순서·전체 파라미터·서버/Mac 명령: [두 교차로 실행 안내](docs/corridor2.md).
- 선택 OSM 사례: [세종대 기록](docs/sejong2_fixed.md).

**원격 Linux 터미널에서 먼저 입력할 명령:**

```bash
cd "/path/to/RL/experiments/fourphase-dqn-comparison"
.venv/bin/python scripts/build_corridor2.py
```

생성 성공 후 모의 연결 검사와 고정신호/규칙 실행으로 진행한다.

## 8. 공식 개발 자료

- [SUMO PlainXML](https://sumo.dlr.de/docs/Networks/PlainXML.html): 도로와 신호 입력.
- [SUMO TraCI](https://sumo.dlr.de/docs/TraCI.html): 상태 조회와 제어.
- [Gymnasium](https://gymnasium.farama.org/): reset/step 환경 인터페이스.
- [Stable-Baselines3 DQN](https://stable-baselines3.readthedocs.io/en/v2.9.2/modules/dqn.html): 현재 사용하는 vanilla DQN.

이번 계획의 성공 기준은 가상 두 교차로에서 재현 가능한 비교 실험을 완성하고,
좋아지는 조건과 나빠지는 조건을 로그·완료율·반복 실행으로 설명하는 것이다.
