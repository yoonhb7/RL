**한 문장 연구 주제**  
> 혼합 교통수요에서 학습한 DQN, Double DQN, Dueling DQN을 동일한 SUMO 4현시 단일 교차로에 적용하여, 저·중·고 교통량별 이동시간·처리량·대기열·학습 안정성을 공정하게 비교한다.

**구현 상태:** `fourphase` 환경과 공통 Replay·Truncation bootstrap·마스크·검증 J 기반 모델 저장에 DQN / Double DQN / 순수 Dueling DQN을 연결했다. Double은 타깃 계산만, Dueling은 V/A 출력 구조만 바꾼다. 학습 순서는 균형 저·중·고를 별도 시드로 섞어 고정하며 ±10% 변동은 기본 실험에서 사용하지 않는다. 사용자가 세 알고리즘 모두 시드 42에서 200에피소드 학습을 완료했다. 모델마다 학습 200회·검증 90회의 검사가 통과했고, 공통 설정·학습 순서·수요 입력 해시가 일치한다. 선정된 검증 J는 DQN 32.7863 / Double 33.8332 / Dueling 38.0401이다. 이어 사용자가 독립 수요 평가 60회를 완료했고 평균 테스트 J는 Fixed 34.2252 / DQN 30.2173 / Double 31.5691 / Dueling 37.2622다. 테스트와 검증 결과를 구별하며, 테스트로 모델·설정을 다시 선택하지 않는다. 이는 단일 학습 시드의 예비 평가이며 추가 학습 시드 반복은 나중에 진행한다. 에이전트는 저장 결과를 검사했으며 Python·netconvert·SUMO·테스트·학습을 실행하지 않았다. [환경 안내](docs/fourphase.md)와 [DQN 계열 학습·결과 안내](docs/fourphase_dqn.md)를 따른다. 수정 전 문서는 [v1.0 보관본](docs/archive/fourphase_plan_v1.0_2026-11-15.md)에 보존한다.

## 1. 연구 동기, 질문, 가설

### 1.1 배경

교통신호 DQN 연구는 다양한 보상·네트워크·현시 설계를 사용하기 때문에 논문 간 성능 수치를 직접 비교하기 어렵다. 특히 저교통량에서 드문 대기열을 처리할 때와 고교통량에서 차량이 계속 누적될 때는 같은 신호 정책의 효과가 달라질 수 있다. 이번 연구는 새로운 네트워크를 개발하는 대신 **동일한 도로·State·Action·Reward·학습 예산을 고정**하여 세 DQN 모델의 구조적 차이만 비교한다.

좌회전 전용차로와 별도 보호 좌회전 현시를 포함해 기본 2현시보다 현실적인, 그러나 구현 가능한 수준의 **4현시 교차로**를 사용한다. 현시 순서는 Li et al. (2020)을 참고하고, 교차로 단일 에이전트 설계의 출발점은 IntelliLight (2018)를 따른다. 단, CNN·Phase Gate·Memory Palace를 제거하므로 IntelliLight를 수치적으로 완전 재현하는 프로젝트는 아니다.

### 1.2 연구 질문(RQ)

- **RQ1 (주 질문):** 혼합 교통량으로 학습한 DQN·Double DQN·순수 Dueling DQN의 ATT, Throughput, AQL은 저·중·고 교통량에서 어떻게 달라지는가?
- **RQ2:** 각 모델이 학습 예산을 동일하게 사용했을 때 수렴 속도, 시드 간 변동, 학습 불안정성에는 어떤 차이가 있는가?
- **RQ3:** 저·중·고 수준별로 **어떤 지표에서** 알고리즘 간 우위가 나타나며, 그 결과는 정지차량-초·미완료/미진입 차량을 고려해도 유지되는가?
- **보조 설명 질문:** 녹색시간 배분과 신호 전환 횟수가 달라질 때 혼잡 지표는 어떻게 변하는가?

### 1.3 사전 가설 — **검증 결과 아님**

- **H1:** Double DQN은 일반 DQN보다 Q-value 과대추정 위험이 낮아 일부 혼잡 조건에서 성능 변동이 작을 수 있다.
- **H2:** Dueling의 V/A 분리 효과는 2행동 신호제어에서는 항상 이득을 주지 않을 수 있다.
- **H3:** 교통량이 증가하고 대기열이 포화에 접근할수록 세 모델의 성능·안정성 차이가 달라질 수 있다.

H1–H3는 방향을 정해 둔 **가설**일 뿐이며, 모델별 우수성을 사전에 단정하지 않는다. Pálos & Huszák (2020)에서도 순수 Dueling DQN이 모든 지표에서 기본 DQN을 능가하지는 않았다(원문 Table II).

### 1.4 연구 기여의 적절한 표현

**기대할 수 있는 기여:** (1) 같은 4현시·좌회전 도로에서 세 DQN의 독립적 통제 비교, (2) 혼합수요 학습 정책의 교통량 수준별 성능 분석, (3) 완료 차량 편향을 보완하는 대기/미진입/미완료 지표와 시드 변동 보고.  
**주장하면 안 되는 기여:** 완전히 새로운 DQN 알고리즘 개발, DQN 변형의 최초 교통신호 비교, 실제 도시 전체 신호제어 성능의 보편적 우월성, 관측하지 않은 교통량으로의 엄밀한 외삽 일반화.

## 3. SUMO 도로망 구축

### 3.1 도로 구조 — [제안]

- 교차로 **1개**, 진입 방향 N/S/E/W **4개**.
- 각 방향은 **진입 2차로 + 진출 2차로**, 도로 전체 **왕복 4차로**. 도로 전체로 보면 교차로 앞 진입 차로 **총 8개**와 각 방향 진출 차로 **총 8개**.
- 접근로 **왼쪽 차로 = 보호 좌회전 전용**, **오른쪽 차로 = 직진 전용**(우측통행 기준). 초기 실험에서 우회전 및 유턴 경로는 생성하지 않는다.
- 진입·진출 링크 길이 **500m(초기 제안)**, 속도 제한 **50km/h(초기 제안)**. 실제 고수요 시 대기열이 상류 경계를 점유하면 링크 길이·수요를 파일럿으로 재검토한다.
- 차량 유형은 동일한 일반 승용차 1종을 기본으로 하며, 운전자 매개변수·추종모형·최소 간격·차로 변경 설정을 모든 알고리즘에 똑같이 적용한다.
- 좌회전 경로는 반드시 좌회전 전용 차로와 연결하고, 직진 경로는 직진 전용 차로와 연결한다. SUMO NetEdit `Connections` 모드에서 잘못된 교차·우회전 경로가 없는지 확인한다.
- 지도 기반 실제 도로 재현, 보행 신호, 버스·대형차·자전거, 긴 연결도로·다중 교차로는 **이번 범위 밖**이다.

**중요:** 좌회전 신호를 사용하려면 좌회전 차량만 별도로 추적해야 하므로, 총 대기차량 수만 집계하는 상태는 후보에서 후순위로 둔다.

### 3.2 신호 현시와 안전 전환 — [원문 + 제안]

| 현시 번호 | 녹색으로 통행 가능한 이동류 | 나머지 이동류 | 다음 녹색 현시 |
|---|---|---|---|
| P0 | 남→북, 북→남 **직진** | 적색 | P1 |
| P1 | 남북 접근로에서 각각 **보호 좌회전** | 적색 | P2 |
| P2 | 동→서, 서→동 **직진** | 적색 | P3 |
| P3 | 동서 접근로에서 각각 **보호 좌회전** | 적색 | P0 |

- [원문, Li et al. §3.1.2] **녹색 현시 고정 순서 P0→P1→P2→P3→P0** 및 행동 `유지/다음 현시 전환`.
- [원문, Li et al.] 황색 3초, 결정 간격 15초. **전적색 1초는 해당 논문의 확인된 값이 아니라 우리 프로젝트 제안**이다.
- [제안] 현시 전환은 **현재 녹색 종료 → 종료 이동류만 황색 3초 → 전 이동류 적색 1초 → 다음 녹색**. 실제 교차 충돌 여부는 SUMO에서 4현시 × 전환 조합을 시각적으로 검증한다.
- [제안] 이 순서를 4 녹색 + 4 황색 + 4 전적색의 **12개 내부 TLS phase**로 정의한다. 에이전트는 내부 phase 번호를 직접 선택하지 않고 **2개 RL 행동**만 고른다.
- [공식 문서] SUMO는 TraCI `setPhase`로 사전 정의한 황색·전적색 phase로 넘기고 이후 다음 phase로 자동 진행할 수 있다. `setRedYellowGreenState`로 매 순간 램프를 직접 지정하는 방식은 안전 전환을 우리가 모두 책임져야 하므로 초기 구현에서 피한다.

### 3.3 시간 규약을 엄밀히 정의 — [제안]

다음 규칙을 **모든 RL 모델과 모든 실험**에 공통 적용한다.

| 제어 항목 | 권장 초기값 | 의미 |
|---|---|---|
| SUMO simulation step | **1초** | 교통·차량 상태 업데이트 단위 |
| RL 의사결정 간격 Δ | **15초** | 에이전트가 행동을 선택하는 주기 |
| `a=0` 유지 | 현재 녹색 15초 지속 | 그 15초 동안 매 초 차량 통계 누적 |
| `a=1` 전환 | 현재 황색 **3초** + 전적색 **1초** + **다음 녹색 11초** | 총 15초; 다음 행동은 새 녹색이 11초 경과한 시점에서 수행 |
| 최소 녹색 | **11초** | 전환 직후 다음 행동 시점에 이미 충족되도록 설계 |
| 최대 녹색 | **60초 상한(제안)** | `a=0`을 하면 60초를 초과하는 상황에서는 유지 불허 |
| 시작 조건 | P0 녹색·경과 0초·빈 도로 | 초기 한 번은 최소 녹색 이전 전환 금지 |

**시간 정합성:** 모든 상태전이 `(s,a,r,s')`는 **정확히 15초가 지난 뒤** 수집한다. 15초 중 황색·전적색 시간도 보상 및 정지차량 계측에 포함한다. 전환 때 총 시간이 더 길어지는 설계와 섞지 않는다. 에이전트는 녹색 시작 직후의 경과시간을 상태로 받아야 한다.

**유효 행동 처리:** 최대 녹색을 넘기는 `유지`는 액션 마스크로 금지하여 `전환`만 허용한다. 학습 데이터에 `유지`를 기록하고 실행은 강제로 `전환`시키는 방식은 피한다. Q-target의 다음 행동 선택에서도 동일한 액션 마스크를 적용해야 한다. 물리적 충돌을 피하기 위한 신호 전환은 환경 제약으로 처리하며 DQN/Double/Dueling 모두 **같은 규칙**을 사용한다.

**현시의 고정 순서가 갖는 한계:** 좌회전 수요가 없더라도 좌회전 현시를 건너뛰지 못한다. 이는 환경 가정으로 명시하고, 본 연구에서 현시 건너뛰기나 현시 순서 최적화는 하지 않는다. 각 현시별 녹색 배분·전환 횟수는 진단 지표로 기록한다.

### 3.4 환경 구축 검증 체크리스트

- [ ] N/S/E/W 진입 2차로가 각각 지정된 직진·좌회전 경로로만 연결되는가?
- [ ] P0~P3 중 충돌하는 이동류가 동시에 녹색이 되는 경우는 없는가?
- [ ] 모든 녹색 전환에 황색 3초, 전적색 1초가 정확히 들어가는가?
- [ ] DQN이 전환 명령을 내리지 않아도 SUMO의 기본 자동 시간표가 뜻하지 않게 개입하지 않는가?
- [ ] 모든 RL 행동 구간이 정확히 15 SUMO 초인가?
- [ ] 초기 상태·종료시간·차량 유형·수요 파일·신호 안전 규칙이 알고리즘 간 일치하는가?

## 4. MDP 설계 — State / Action / Reward

### 4.1 관측(State) — **S1 확정**

**S1 [프로젝트 설계]: 차로별 대기열 + 현시 + 녹색 경과시간**

- 8개 진입차로(방향 4 × 좌회전·직진 2)의 **정지차량 수** `q_1,…,q_8`.
- 현재 녹색 현시 `P0,P1,P2,P3`를 나타내는 **4차원 one-hot**.
- 현재 녹색 경과시간을 최대 녹색 60초로 나눈 **1차원 실수**.
- 입력은 **8+4+1=13차원**. 논문의 원래 State를 그대로 복사한 수치가 아닌 프로젝트 설계다.

**부분관측 한계:** 접근 차량의 속도·위치·미래 유입률·외부 대기열을 모두 담지 않는 압축 관측이다. 완전한 Markov State라고 주장하지 않는다. S2(접근 차량 수/평균속도 추가)는 주 실험에 사용하지 않는다.

**정규화 기준:** 차로별 대기열을 예상 저장 가능 차량 수(차로 길이, 차량 길이 및 최소 간격 기준) 등 **학습 전 확정된 기준**으로 나눠 정규화한다. 평가 수요를 보고 스케일을 재계산하지 않는다. 시험 차량이 관측 범위 밖으로 넘쳐도 숨겨지지 않도록 입력 차로 길이와 미진입 지표를 함께 기록한다.

구현은 `C_hat=max(1, SUMO 차로 길이/(차량 길이+minGap))`라는 고정 근사를 사용한다. 정규화 후 **Clipping을 적용하지 않는다**. Gymnasium 범위는 앞 8개 `[0,∞)`, One-hot 4개와 `g/60`은 `[0,1]`이다. 원시 정지차량 수·스케일·정규화 관측을 기록하고 유한값·범위·One-hot 합을 검사한다.

**출처와 차이:** IntelliLight는 차로별 대기열·차량 수·대기시간·이미지·위상 등을 사용했다(§4.2); FRAP은 이동류 차량 수와 현시를 사용했다(§3.2); Pálos & Huszák은 4방향의 차량 수·점유율·속도와 현재 현시를 사용했다(§III). **S1은 이들을 근거로 간결하게 구성한 새 상태**이며 논문 그대로가 아니다.

**검증 절차:** 직진·좌회전 대기열 분리, 고정 스케일, 경과시간·행동 마스크를 파일럿에서 확인한다. 관측은 세 알고리즘에 동일하게 적용하며 본 실험 중 변경하지 않는다.

### 4.2 행동(Action) — **확정**

| 행동 | 의미 | 환경 실행 |
|---|---|---|
| 0 | 현재 녹색 유지 | 15초 연장 |
| 1 | 다음 녹색으로 전환 | 황색 3초 + 전적색 1초 + 다음 녹색 11초 |

현시 순서를 무작위로 선택하는 4행동 또는 FRAP처럼 8현시 중 직접 선택하는 방식은 **이번 범위에 포함하지 않는다**.

### 4.3 보상(Reward) — **R1 확정**

**R1 [프로젝트 설계]: 15초 구간 평균 정지차량 수의 음수**

\[
R_k=-\frac{1}{15}\sum_{j=1}^{15}\sum_{\ell\in\mathcal L_{\mathrm{in}}} q_\ell(15k+j)
\]

- `q_ℓ(τ)`: 시점 τ에 진입차로 ℓ에서 **0.1m/s 미만**으로 정지한 차량 수(SUMO `getLastStepHaltingNumber`).
- 모든 녹색·황색·전적색 시간을 포함하여 누적한다.
- 각 `simulationStep()` 직후 매초 측정하며 진입 8차로만 포함한다. 내부 연결차로·진출차로의 정지차량은 R1에서 제외한다.
- 대기열을 줄이는 목적과 정합적이고, 별도 가중치가 없어 알고리즘 공정 비교가 쉽다.
- **한계:** 처리량을 직접 최적화하지는 않으므로, Throughput·미진입/미완료 차량을 별도 계측해야 한다.

**대안 R2 [원문 아이디어·미채택]:** FRAP의 이동류 평균 대기열 보상. R1과 목적은 유사하지만 분모 및 이동류 집계 정의를 확인하고 비교한다.

**대안 R3 [원문 아이디어·미채택]:** IntelliLight의 6항목 가중 보상(대기열, 지체, 대기시간, 전환, 통과량, 이동시간; 원문 Eq. 3). 우리 프로젝트에서는 가중치를 튜닝해야 하고 결과 원인을 해석하기 어려워 기본안으로 권하지 않는다.

**고정 원칙:** R1 하나를 모든 모델·교통량에 적용한다. 할인·스케일 변환 전의 원시 보상합을 기록하고 `W_stop,in = -15 × Σr`를 매초 로그와 대조한다. 고수요에서 R1이 외부 Pending의 차이를 구분하지 못할 수 있으므로 Pending·처리량을 함께 분석한다. 보상 변경은 별도 후속 실험으로 다룬다.

### 4.4 Continuing Task와 Truncation — **확정**

- 교통신호 제어는 지속적 문제이며 3,600초는 외부 관측 시간 제한이다. 남은 시간을 관측에 추가하지 않는다.
- 240번째 행동 후 `terminated=False`, `truncated=True`를 반환한다. 실제 마지막 관측과 유효 행동 마스크를 **reset 이전에** 저장한다.
- 학습 타깃은 `r + γ × (1-terminated) × Q_next`이며, Truncation에서도 bootstrap한다. DQN/Dueling은 유효 행동의 target 최대값, Double은 유효 행동의 online argmax를 target에서 평가한다.
- Replay는 `(state, action, reward, next_state, terminated, truncated, next_action_mask)`를 보존한다. 탐색·탐욕 선택·Q-target에 같은 행동 마스크를 적용한다. 3,600초라는 이유로 마스크를 모두 False로 만들지 않는다.
- 환경 reset 시 차량·신호·에피소드 통계만 초기화한다. Online/Target network, Adam 상태, Replay, 전체 학습 카운터와 ε 감소 진행은 유지한다.
- 충돌·프로그램 오류에 의한 중단은 별도 실행 실패이며 정상 Termination/Truncation으로 Replay에 넣지 않는다. 시간 제한 자체의 종료 보상·페널티는 없다.

## 5. 교통 수요 생성 및 교통량 수준 설정

### 5.1 본 실험의 수요 원칙

1. 4개 방향의 총 유입비 **1:1:1:1**, 각 접근로에서 **직진 75% / 보호 좌회전 25%**(예시)로 고정한다. 우회전·유턴 0%.
2. 저·중·고 간에는 **총 교통량만 변화**시키며 방향비·좌회전 비율·차량 성능·도로 구조·현시 순서는 유지한다.
3. 도착 시간은 포아송 도착 또는 동등한 무작위 배차 방식으로 생성하되, **실제 생성된 차량의 예정 출발 시각 목록**을 파일에 저장해 모델별로 똑같이 사용한다.
4. 일정한 수요와 혼합 수요의 정의를 분리한다. 본 실험의 ‘혼합 학습’은 **에피소드별로 저·중·고 수요를 무작위로 선택해 하나의 정책을 학습**하는 것이다. 한 에피소드 안에서 극단적인 방향 반전을 필수로 구현하지 않는다.
5. **0~3,600초 전체에 같은 수요 생성 규칙**을 유지한다. 3,000초 수요+600초 정리는 사용하지 않는다. 생성기는 같은 도착 과정으로 60초 뒤까지 배차를 보존하되, 3,600초 이후 예정 차량은 `N_due`와 Pending 부담에서 제외한다. 배차시각은 1초 SUMO 격자에 맞춰 내림한다.
6. 현재 구현의 총 수요율 **1,200/1,800/2,400 veh/h**는 파일럿 후보이며 최종 혼잡 수준으로 검증된 값이 아니다. 파일럿 시드 42는 향후 독립 검증·테스트 시드로 재사용하지 않는다.

### 5.2 저·중·고 수요는 파일럿에서 정한다 — [중요]

논문에 있던 특정 차량 대수를 그대로 가져오지 않는다. 보호 좌회전 4현시, 직진·좌회전 용량과 링크 길이가 달라졌기 때문이다.

**파일럿 절차**  
(1) Fixed-time 4현시로 수요를 낮은 수준부터 점차 증가시키며 시뮬레이션 1시간 동안 처리량·평균 대기열·미진입 차량을 관찰.  
(2) 각 이동류별 수요 `v_m`과 해당 신호 운영에서의 실질적 처리용량 `c_m`을 근사해 **병목 수요/용량비** `ρ≈max_m(v_m/c_m)`를 참고. 이 값은 고정현시·차로 구성에 의존하므로 만능 상수가 아니다.  
(3) 아래 **초기 목표 범위**를 사용하되, 실제 고수요에서 출발 지연·미완료가 너무 심하면 다시 보정.

| 그룹 | 병목 수요/용량비의 초기 목표 [제안] | 파일럿에서 기대하는 현상 |
|---|---:|---|
| Low | 약 **0.35–0.50** | 대기열 대체로 짧고 대부분 정상 통과 |
| Medium | 약 **0.60–0.75** | 대기열이 발생하되 대부분 해소 가능 |
| High | 약 **0.85–1.00** | 높은 이용률·지속적 대기가 나타날 수 있으나 초기부터 완전한 gridlock은 회피 |

**주의:** 위 비율과 실제 veh/h 수치는 **제안이며 아직 실측/검증된 값이 아님**. 신호 4현시로 인해 직진·좌회전 병목이 다르므로 ‘총 유입량’만으로 혼잡 수준을 규정하지 않는다. 파일럿 결과에 최종 차량/시간을 확정한다.

### 5.3 Training / Validation / Test 분리

| 자료군 | 내용 | 역할 | 공유 방식 |
|---|---|---|---|
| Train | Low/Medium/High 각 1/3 확률로 에피소드 추출; 각 그룹 중심율에서 소폭 변동(예: ±10%); 서로 다른 차량생성 시드 | 혼합 수요 정책 학습 | 같은 학습 반복 번호끼리는 세 알고리즘에 **같은 수요 시퀀스** 제공 |
| Validation | 저·중·고 각 독립 배차 시드 **3개**(제안) | 보상/상태 최종화, 공통 하이퍼파라미터 파일럿, 체크포인트 선택 | 훈련에 사용하지 않음 |
| Test | 저·중·고 각 **5개** 독립 배차 시드(제안) | 최종 비교·통계 | 모든 알고리즘과 Fixed-time에 **동일한 테스트 시드** 사용 |

훈련과 평가에 모두 Low/Medium/High가 있다는 사실은 데이터 누출이 아니다. **같은 차량 시간표/시드를 훈련과 테스트에 재사용하는 것이 문제**다. 따라서 연구 질문은 ‘미지의 교통량 수준으로 외삽’이 아닌 **학습에서 경험한 교통량 범위 안의 새로운 도착 패턴에 대한 성능 비교**로 표현한다.

## 6. 세 알고리즘과 공정 비교 설계

### 6.1 반드시 지킬 알고리즘의 분리

**DQN** — 온라인 Q 네트워크와 타깃 Q 네트워크를 가진 기본 Q-learning 기반 신경망. 다음 상태의 타깃값을 타깃 네트워크의 최대 Q값으로 계산한다.

\[
y^{\mathrm{DQN}}=r+\gamma\max_{a'\in\mathcal A(s')}Q_{\mathrm{target}}(s',a')
\]

**Double DQN** — **온라인 네트워크가 다음 행동을 선택**, 타깃 네트워크가 **그 행동의 가치**를 평가.

\[
y^{\mathrm{Double}}=r+\gamma Q_{\mathrm{target}}\Big(s',\operatorname*{arg\,max}_{a'\in\mathcal A(s')}Q_{\mathrm{online}}(s',a')\Big)
\]

**순수 Dueling DQN** — Q-network의 끝을 **상태가치 V와 이점 A의 별도 출력**으로 나눈다. 타깃 계산 자체는 위의 **DQN 방식**을 사용하여 Double 알고리즘을 섞지 않는다.

\[
Q(s,a)=V(s)+A(s,a)-\frac{1}{|\mathcal A|}\sum_{a'}A(s,a')
\]

`Double Dueling DQN`/`D3QN`은 위 두 변형을 결합한 **제4의 모델**로, 이번 프로젝트에서 제외한다. 위 두 타깃 식은 비종료 상태 기준이다. 실제 `terminated=True`에서만 미래 항을 0으로 만들며, 외부 Truncation에서는 유지한다.

### 6.2 공통 MLP 및 파라미터 보고 — [제안]

- **기본 공통 Feature Extractor:** `State(13차원) → Dense(64) → ReLU → Dense(64) → ReLU`.
- **DQN·Double:** 최종 2개 Q-value를 출력하는 선형층. **입력/출력 구조는 완전히 동일**, 타깃 계산만 다르다.
- **Dueling:** 똑같은 공통 은닉층 뒤에 `V(s)` 1개 출력 헤드, `A(s,0),A(s,1)` 2개 출력 헤드. 위 식으로 Q값을 합친다.
- **S1(13차원) 기준 파라미터 수:** DQN=Double **5,186개**; Dueling **5,251개**(두 헤드는 각각 선형층 1개). Dueling은 구조상 반드시 차이가 나므로, 숨겨서 '모든 모델 완전히 동일한 네트워크'라고 표현하지 않는다.
- State 차원이나 분리 헤드 구조가 바뀌면 파라미터 수를 **실제 구현에서 다시 계산**한다.

### 6.3 학습 하이퍼파라미터 (모두 **프로젝트 초기 제안**, 원문값 아님)

| 항목 | 제안값 | 공정성 규칙 |
|---|---:|---|
| 온라인 optimizer | Adam | 동일 |
| 학습률 | **0.0005** | 동일; 필요 시 검증 데이터만 사용하여 함께 수정 |
| 할인율 γ | **0.99 / 15초 행동 간격** | 동일 |
| 손실 | Huber loss | 동일 |
| Replay buffer | **50,000 transitions** | 동일 |
| Batch size | **32** | 동일 |
| 학습 시작까지 경험 수 | **1,000 transitions** | 동일 |
| 학습 빈도 | 의사결정 **1회마다 1 minibatch 업데이트** | 동일 |
| Target network 업데이트 | **500회 의사결정마다 hard copy** | 동일 |

| 독립 학습 시드 | **3개**, 여유 시 5개 | 모델 간 동일 번호 사용하되 모델 초기화는 독립 |

**체크포인트 선택 확정:** 매 20에피소드마다 Validation 3수준 × 3시드의 J를 계산한다. 수준별·수요 시드별 동일 가중 평균이 최소인 체크포인트를 **각 독립 학습 실행에서** 선택한다. 동률이면 먼저 저장한 체크포인트를 유지한다. ATT/Throughput 또는 Test 결과로 나중에 교체하지 않는다. 학습 보상은 원시 정지차량 수에 비례하고 검증 J는 차량당 부담을 동일 수준 가중으로 평가하므로 목적의 차이를 명시한다.

## 7. 비교 기준선과 실험 매트릭스

### 7.1 Fixed-time 기준선 — [제안]

- 같은 4개 녹색 현시·동일 안전 전환을 사용하되 **고정된 녹색 시간표**로 반복.
- 시작 후보: P0 직진 30초 / P1 좌회전 15초 / P2 직진 30초 / P3 좌회전 15초 + 전환 구간마다 황색 3초·전적색 1초 → **고정 주기 106초**.
- 이 시간표는 문헌의 최적값이 아니라 **우리 제안값**이며, 학습 전 파일럿·Validation을 이용한 간단한 조정은 허용한다. Test 결과에 맞춰 변경하지 않는다.
- Fixed-time은 학습을 하지 않는다. 모든 Test 교통량 × 수요 시드에서 모델과 동일한 조건으로 반복 실행한다.

### 7.2 9개 본 비교 조건

| 학습된 알고리즘 | Low 평가 | Medium 평가 | High 평가 |
|---|---|---|---|
| **DQN** | DQN-L | DQN-M | DQN-H |
| **Double DQN** | Double-L | Double-M | Double-H |
| **Dueling DQN** | Dueling-L | Dueling-M | Dueling-H |
| **Fixed-time (기준선)** | FT-L | FT-M | FT-H |

- **9개 알고리즘 평가 조건 + Fixed-time 3개 기준선 조건**. ‘3개 모델을 학습한다’는 것은 알고리즘 종류 기준이며, **독립 시드 3개를 쓰면 실제 학습 실행은 9개**다.
- [제안] 각 알고리즘 × 학습 시드 3개 × 평가 수요 수준 3개 × Test 배차 시드 5개 = **135회 Test 실행**. Fixed-time: 3수준 × 5수요 시드 = **15회**. 합계 **150회 테스트 시뮬레이션**(Validation 및 파일럿 별도).
- 가장 중요한 통제: **동일 평가 교통량, 같은 차량 출발시간·경로 목록·차량 종류·시작 상태, 같은 3,600초 종료시간**에서 비교한다.

### 7.3 추가 실험은 1개만 선택(선택 사항)

**방향별 불균형에 대한 스트레스 테스트:** 총 차량 수와 직진/좌회전 비율을 유지한 채 **남북:동서 유입 비율을 70:30**으로 바꾸어 혼합수요에서 학습한 정책을 **재학습 없이 평가**한다. 이를 저·중·고 평가와 섞지 않고 **별도 선택적 분석**으로 표기한다. 시간이 부족하면 삭제한다. 이 실험은 동일 총수요에서 분포 이동에 대한 강건성을 보는 것이며, 미지의 교차로 구조 일반화나 새로운 알고리즘 개발로 과장하지 않는다.

## 8. 지표 정의, 데이터 수집, 통계

### 8.1 본 평가 지표

| 지표 | 본 연구의 정의 | 계산·주의점 |
|---|---|---|
| **ATT (s)** | 평가 종료 전 **완료한 차량**의 실제 이동시간 평균 | SUMO `tripinfo.duration`으로 산출; **미완료가 많으면 완료 차량만의 선택 편향**이 있음 |
| **Throughput (veh / 3,600s)** | 시험 구간 동안 목적지까지 **도착 완료한 차량 수** | 유입/완료를 혼동하지 않는다. 여러 모델에 같은 수요 계획 사용 |
| **AQL (veh)** | 매 초 **8개 진입차로의 정지차량 수 합**을 구한 뒤 3,600초 평균 | 분모/차로 수를 고정; 평균 차로당 대기열을 쓸 경우 별도 지표명 사용 |
| **Stopped vehicle-seconds (veh·s)** | 각 초의 전체 정지차량 수를 시간에 대해 합산 | 완료 차량만이 아니라 관측 구간 내 정지차량 전체를 반영 |
| 미진입 차량 수 | 예정 차량 수 − 실제 SUMO 네트워크에 출발한 차량 수 | 과밀로 네트워크에 진입하지 못한 경우 확인 |
| 미완료 차량 수 | 실제 출발 차량 수 − 종료 전 도착 완료 차량 수 | 종료 시 네트워크에 남은 차량(별도 제거·teleport가 없다는 조건) |
| 학습 안정성 | 학습/검증 곡선과 독립 학습 시드 간 최종 성능 분산 | 평균, 표준편차, 개별 시드 점, 검증 곡선을 함께 보고 |
| 녹색 배분·전환 수 | 각 현시 녹색 누적시간/전체, 전환 횟수/시간 | 같은 ATT라도 과도한 빈번 전환인지 해석 |

**검증 점수 J:** `J=(W_stop,in+W_pending)/N_due` (초/예정 차량). `W_stop,in`은 R1과 같은 진입 8차로의 정지차량-초, `W_pending=Σ초 N_pending,due`는 매초 미진입 차량 수를 누적한 차량-초다. 마지막 Pending 개수만으로 대체하지 않는다. `N_due`는 3,600초 이전 예정 차량 수이며 항상 양수다. 네트워크 전체 정지차량-초는 별도 진단 지표로 기록한다. J는 ATT가 아니다.

**안전 및 실행 상태:** `max-depart-delay=-1`, `time-to-teleport=-1`, `collision.action=warn`, `collision.check-junctions=true`를 공통 적용한다. 매초 충돌·Teleport를 확인하고 최초 이벤트의 시간·차량·현시·차로·SUMO 충돌 유형과 경고 로그를 보존한 뒤 중단한다. SUMO의 충돌 판정에는 minGap 위반도 포함될 수 있으므로 원인은 사후 분류한다. 비정상 실행의 수·원인을 보고하고 성공한 실행만 골라 비교하지 않는다. 심각한 혼잡·정체는 3,600초까지 유효한 성능 결과로 유지한다. 환경 동작을 바꾸는 오류 수정 시 관련 학습·평가에 같은 환경 버전을 적용한다.

**SUMO 출력 활용 [공식 문서]:** `lane.getLastStepHaltingNumber`(0.1m/s 미만 정지), `tripinfo`(`depart`, `departDelay`, `arrival`, `duration`, `waitingTime`, `timeLoss` 등), TraCI `simulation.getDepartedNumber`, `getArrivedNumber` 계열 카운터, 전체 통계/차량 예정 배차 목록을 병행한다. 기본 `tripinfo`는 완료 차량 위주로 기록하므로 **미완료·미출발 차량 추가 출력 옵션**(`--tripinfo-output.write-unfinished`, `--tripinfo-output.write-undeparted`)도 검토한다. 차량이 삽입되지 못한 `departDelay`는 ATT만으로 나타나지 않으므로 별도 기록한다.

**관계식 검증:** 원칙적으로 `예정 = 미진입 + 출발`, `출발 = 도착 + 종료 시 주행 중`이어야 한다. 다만 시뮬레이터의 강제 삭제/teleport가 발생하면 이를 별도 항목으로 기록해야 하며, 과밀 시 차량이 자동으로 없어지는 상황을 그냥 높은 처리량으로 착각하지 않는다.

### 8.2 결과 해석과 통계 처리

1. **같은 교통수요 시드끼리 페어링**하여 알고리즘별 차이를 계산한다. Low/Medium/High별로 별도의 비교 표 작성.
2. 독립 **학습 시드 3개**의 모델별 결과를 먼저 각각 확인한다. 3개는 통계적 확신에 한계가 있으므로 가능하면 5개로 늘리고, 표준편차·개별 점을 공개한다.
3. 매 학습 시드별 5개 Test 수요 시드에 대해 평균을 계산한 뒤, 학습 시드 사이 분포를 요약한다. 15개 관측을 모두 완전 독립 학습 반복처럼 취급하지 않는다.
4. 95% 신뢰구간을 보고할 경우 학습 시드와 평가 수요 시드의 **계층 구조**를 고려한 재표본화 또는 간결한 시드별 평균/표준편차 보고를 사용한다.
5. **교통량별 절대 ATT·AQL 차이**와 **같은 교통량에서 모델 간 상대 차이**를 구분한다. 서로 다른 논문에서 제시한 성능 개선율을 그대로 끌어와 직접 비교하지 않는다.
6. 고수요에서 ATT가 좋아 보여도 **Throughput이 낮고 미진입·미완료가 많다면 성공이라고 단정하지 않는다**. 최소 3개 핵심 지표와 미완료 지표를 함께 해석한다.

### 8.3 필수 결과물 그래프·표

- **그래프 1:** 저·중·고별 ATT (DQN, Double, Dueling, Fixed-time), 독립 시드 점/오차 범위.
- **그래프 2:** 저·중·고별 Throughput 및 미완료·미진입 차량 수(쌍으로 표시).
- **그래프 3:** 저·중·고별 AQL 및 stopped vehicle-seconds.
- **그래프 4:** 같은 학습 예산 기준 모델별 학습/Validation 곡선(3 시드 평균·변동).
- **그래프 5(설명용):** 4현시 녹색시간 비율과 시간당 신호 전환 횟수.
- **표 1:** 교통량 그룹별 실제 배차 차량 수/시간, 좌회전 25%, 병목 수요/용량비와 파일럿 판정.
- **표 2:** 네트워크 구성과 공통 하이퍼파라미터, 모델별 총 파라미터 수.
- **표 3:** 9조건 + Fixed-time의 핵심 지표 평균/표준편차 및 시드 수.

## 9. 구현 순서(코드는 이 문서에 포함하지 않음)

### 단계 1 — 순수 교통 시뮬레이션과 Fixed-time 확보

1. 명시적 노드·차로·연결·신호 XML과 netconvert로 4방향 왕복 4차로를 생성하고 NETEDIT/GUI로 확인.
2. 4개 녹색 현시, 각 전환 황색·전적색 단계 정의; 고정 신호로 모든 OD 경로가 정상 운행하는지 확인.
3. 직진·좌회전 배차 데이터를 만들어 3,600초 동안 실행; `arrived/departed/halting` 계측이 맞는지 확인.
4. Fixed-time 기준선에서 기초 처리량과 수요-용량 병목을 파일럿 측정.
5. Low/Medium/High 수요율 범위를 결정하고 파일로 저장.

**통과 조건:** 충돌/잘못된 신호/경로 불능 없음; 4현시 순환·차로별 경로·대기열 측정이 정상.

### 단계 2 — 공통 RL 환경 래퍼

1. TraCI와 연결해 `reset → observation → valid action → 15s 실행 → reward → next observation → 종료` 인터페이스 정의.
2. 액션 마스크(최소·최대 녹색), 황색·전적색, 15초 보상 누적, 3,600초 종료를 구현 전 설계서와 대조.
3. 랜덤 행동 에이전트로 1개 에피소드 실행하고 `유지/전환`, 상태 차원, 목적지 완료 개수, reward 로그 확인.
4. 학습/검증/테스트 생성 시드가 중복되지 않는지 점검.

**통과 조건:** 안전 신호 강제, 동일 사건의 보상 중복 없음, 모든 데이터 저장, episode 종료 후 깨끗한 reset.

### 단계 3 — 단일 DQN 기준선

1. 공통 MLP 구조로 DQN 1개를 먼저 소규모 학습(예: 20에피소드)해 action 실행과 값 업데이트가 정상인지 확인.
2. Replay/target/epsilon/logging과 Validation checkpoint 시험.
3. 확정한 S1/R1 계산을 검증하고 공통 하이퍼파라미터·훈련 예산을 Test 이전에 확정.

**통과 조건:** Fixed-time과 동일한 수요에서 평가 가능하고, 모델이 불법 현시를 선택하지 않음. 성능이 당장 Fixed-time보다 높아야만 다음 단계로 가는 것은 아님.

### 단계 4 — Double·Dueling 추가

1. **Double:** 네트워크는 DQN과 같게 두고 target 생성식만 변경.
2. **Dueling:** 공통 feature 층을 유지하고 V/A 분기만 추가. pure Dueling은 Double target을 사용하지 않음.
3. 모델별 파라미터 수, loss·epsilon·target update·replay 통제, seed 체크리스트 검증.

**통과 조건:** 3개 알고리즘이 동일한 교통환경과 입력/행동 보상으로 작동하며, 차이는 의도된 target 구조 또는 출력 head뿐임.

### 단계 5 — 본 학습 및 평가

1. 3개 알고리즘 × 3개 학습 시드, 혼합수요 에피소드 순서와 예산을 맞춰 학습.
2. Validation에서 체크포인트를 선택하고 설정·가중치 저장.
3. 고정된 Test 파일 3수준 × 5시드로 9개 학습된 정책과 Fixed-time 실행.
4. ATT·Throughput·AQL과 미진입·미완료 등 모든 지표를 모아 비교.

### 단계 6 — 분석 및 보고

1. 교통량별 성능, 학습곡선, 각 현시의 실제 시간 배분, 고수요의 ATT 편향 확인.
2. 가설 H1–H3를 지지/불지지/판단 유보로 구분.
3. 연구 한계(단일 교차로·가상 수요·4현시 고정순서·소수 학습 시드·현실 교통 일반화 한계)를 명시.
4. 시간 여유가 있을 때만 **방향별 불균형 평가 1개**를 실시하고 별도 결과로 분리.

## 12. 보고서·발표 구성 권장안

1. **문제 정의:** 혼합 수요에서 학습한 DQN 3종을 저·중·고 교통량별로 평가하는 이유.
2. **관련연구:** IntelliLight 환경, Pálos 비교, Li 4현시, FRAP 대기열·수요 연구.
3. **MDP·안전 설계:** 4방향 왕복 4차로, 4녹색 현시, Action 2개, 신호 전환 시간·마스크.

7. **해석:** 학습 안정성과 교통량별 결과를 신호 배분·대기열·실제 차량 수와 연결.

## 13. 확정 설계와 파일럿에서 확인할 사항

| 의사결정 | 잠정 권장안 | 승인 시점 |
|---|---|---|
| **G1 State** | S1: 진입차로별 정지차량 8 + 현시 one-hot 4 + 경과시간 1 | 설계 확정, 파일럿 계산 검증 |

**최종 핵심 원칙:** S1/R1/J/시간·안전 규칙을 고정한다. 파일럿에서 수요 수준·공통 예산을 보정하되 **세 DQN의 성능을 본 후 모델마다 다르게 정하지 않는다.** Test는 하나의 고정된 실험 규약을 처음부터 끝까지 실행하는 데 사용한다.

## 15. 최종 실행 선언

먼저 왕복 4차로·보호 좌회전 4현시 SUMO 환경에서 Fixed-time과 유효 무작위 행동을 검증하고 DQN 파일럿으로 진행한다. 그 다음 **동일한 환경·관측·행동·보상**에서 DQN·Double DQN·순수 Dueling DQN을 혼합 교통수요로 학습하고, 별도의 Low/Medium/High 수요 파일에서 비교한다. 연구의 중심은 **공정한 학습 및 평가와 교통량별 차이의 근거 있는 해석**이다.
