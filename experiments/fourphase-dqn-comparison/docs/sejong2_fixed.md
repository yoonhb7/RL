# 세종대 인근 두 교차로: OSM 도로망과 고정신호 기준선

2026-11-12부터 이 사례는 **선택 확장 실험**으로 보존합니다. 주 실험은 [가상 연속 교차로 2개](corridor2.md)입니다.

다음 대상은 **화양삼거리 ↔ 어린이대공원역 교차로**입니다.
광나루로를 따라 연결되며, 분리된 차도의 교차점들을 두 개의 제어 교차로로 묶습니다.
이는 **공개 지도 기반의 부분 도로망 + 가정 수요·고정신호 실험**입니다.
현장 교통이나 실제 운영 신호를 재현·보정했다고 주장하지 않습니다.

## 현재 준비한 것

- 2026-11-11 OSM 원본을 `data/osm/`에 내려받아 SHA-256으로 고정했습니다.
- 차량 도로 17개와 두 교차로의 OSM 노드 묶음을 설정했습니다.
- 누락 차로 수와 속도, 교통량·OD·신호시간·Offset을 가정으로 분리했습니다.
- 네트워크 생성기, 유효 차량 경로 생성기, 고정신호 측정기와 오프라인 검사를 작성했습니다.
- 사용자가 첫 도로 생성을 완료했습니다. 신호 2개, 수요 724대, 도달 불가능 OD 0개입니다.
- 첫 고정신호 실행은 충돌·텔레포트 때문에 검증 실패했습니다. 기존 입력·결과는 보존합니다.
- 사용자가 방향별 분리 신호를 적용한 `sumo/sejong2_v2`를 생성·실행했습니다. 724대 전부 진입, 637대 도착, 87대 미완료, 미진입 0대입니다.
- 수정본은 충돌·텔레포트·신호 위반 모두 0이며 집계·안전 검사에 통과했습니다. 전체 테스트의 통과 여부는 아직 확인하지 않았습니다.

검증된 실행 결과는 `results/sejong2/fixed_seed_42_20261111T142956411193Z`에 있습니다.
관측 집단 평균 대기시간은 126.81초, 전체 네트워크 평균 정지 차량은 78.57대입니다.
87대가 종료 시 남아 있으므로 정체가 모두 해소된 기준선은 아닙니다. 주 실험 전환을 위해 이 사례를 다시 만들 필요는 없습니다.

## 첫 실행에서 확인한 문제와 수정

기존 `sumo/sejong2`의 실행 결과는 724대 중 도착 469대, 미완료 215대, 미진입 40대입니다.
669초에 어린이대공원역 내부 차로에서 측면 충돌이 기록됐고 텔레포트가 1회 발생했습니다.
이 결과는 검증된 기준선으로 사용하지 않습니다.

기존 자동 신호는 비보호 좌회전을 포함했습니다. 수정본은 SUMO의 `tls.layout=incoming`으로
진입 방향 하나씩 녹색 30초 → 황색 3초 → 전적색 3초를 주며, 다른 방향은 적색으로 유지합니다.
생성 후 신호 연결의 충돌 관계(foes)·합류, 모든 연결의 녹색 제공, 황색·전적색을 정적으로 검사합니다.
이 검사 자체가 실제 시뮬레이션에서 충돌이 없음을 보장하는 것은 아닙니다.

신호 위반 1건은 Offset 15초 때문에 첫 현시가 중간부터 시작하는데 검사기가 전체 현시 길이와
비교해서 발생한 오탐이었습니다. 저장된 1,200초의 두 신호 기록은 절대 시간표와 모두 일치합니다.
수정한 검사기는 매 물리 스텝 시작시각과 Offset을 사용해 기대 현시·색상을 계산합니다.
충돌·텔레포트 검사는 유지하며 유입량도 줄이지 않습니다.

현장 방문·직접 계수·촬영은 하지 않습니다.
신호 설치 여부와 실제 운영 현시는 이 단계에서 확인한 값이 아니며 두 제어기는 실험 가정입니다.
OSM의 도로 구조와 실제 신호 운영을 구분합니다.

## 1. 원격 Linux: 도로망과 수요 생성

아래는 재현 절차입니다. 기존 `sejong2_v2` 생성은 이미 완료했으므로 반복하지 않습니다.

아래 명령을 **VS Code의 원격 Linux 터미널**에서 실행합니다.
기존 프로젝트 `.venv`의 SUMO 1.28과 sumolib를 사용하며 추가 설치는 없습니다.

```bash
cd "/path/to/RL/experiments/fourphase-dqn-comparison"
.venv/bin/python scripts/build_sejong2.py --output sumo/sejong2_v2
```

생성 과정은 다음과 같습니다.

1. 원본 OSM 해시 검사 → 17개 도로 추출 → 영역 내 구간과 끝점 바로 바깥의 원본 지점 유지.
2. 누락 차로 수·가정 속도 기록 → 두 교차로의 분리된 노드 묶기 → netconvert로 연결·방향별 신호 생성.
3. 가정 Offset 적용 → 충돌 관계·합류·황색·전적색·전체 연결 제공 정적 검사.
4. 경계 진입·유출을 찾고 passenger 차량이 실제로 연결된 최단 경로만 수요로 생성.
5. 두 교차로를 모두 지나는 경로, 신호 개수, 차로·현시 목록과 입력 해시 저장.

생성 성공은 **입력 구성 완료**이며 차량 통행이나 안전 검사까지 통과했다는 뜻은 아닙니다.
실패하면 마지막 오류와 `sumo/sejong2_v2/netconvert_*.log`를 확인합니다.
부분 생성 폴더를 덮어쓰지 않으므로 수정 후 다시 만들 때는 새 출력 폴더를 지정합니다.

```bash
.venv/bin/python scripts/build_sejong2.py --output sumo/sejong2_v3
```

다른 수요 시드는 `--seed 43`과 새 `--output`으로 생성합니다.

## 2. 원격 Linux: 고정신호 측정

수정본 폴더의 생성이 성공한 뒤 실행합니다.

```bash
.venv/bin/python scripts/run_sejong2_fixed.py --scenario sumo/sejong2_v2
```

새 폴더로 만들었다면 해당 시나리오를 지정합니다.

```bash
.venv/bin/python scripts/run_sejong2_fixed.py --scenario sumo/sejong2_v3
```

결과는 자동으로 새 `results/sejong2/fixed_seed_42_<시각>/`에 기록합니다.
입력 사본·해시, 매초 전체/교차로별 대기 차량 수, TripInfo, 평균 대기·통행시간,
미완료·미진입 차량, 충돌·텔레포트·신호 순서 검사를 저장합니다.
`collisions.xml`은 충돌 상세, `signal_violations.json`은 기대/관측 현시 불일치,
`blocked_vehicles.json`은 종료 시 오래 정지한 차량의 차로·경로 진단 정보입니다.

`--seed`는 SUMO 내부 시드만 바꾸며 차량 출발 목록을 재생성하지 않습니다.
교통 수요 자체를 바꾸려면 먼저 생성기의 `--seed`와 새 폴더를 사용합니다.

평균 대기시간은 기존 toy 평가와 같이 출발 예정시각이 Warm-up 이후인 차량 집단의
관측 대기시간이며, 이미 출발한 미완료 차량도 포함합니다.
미진입 차량은 별도 집계합니다. 차량이 남으면 평균값과 완료율을 함께 해석합니다.

## 3. Mac: 두 교차로를 직접 보기

도로 생성이 성공한 뒤 **Mac 일반 터미널**에서 복사합니다.

```bash
mkdir -p "$HOME/rl-term-project/sejong2"
ssh USER@SERVER 'tar -C "/path/to/RL/experiments/fourphase-dqn-comparison/sumo/sejong2_v2" -cf - .' \
  | tar -xf - -C "$HOME/rl-term-project/sejong2"
```

이어 같은 Mac 터미널에서 실행합니다.

```bash
sumo-gui \
  -c "$HOME/rl-term-project/sejong2/sejong.gui.sumocfg" \
  --start \
  --delay 100
```

이번 단계는 **SUMO 자체의 고정신호 재생**이므로 원격 Python 제어 연결 없이 진행됩니다.
`--remote-port`를 붙이지 않습니다. 기존 toy용 SSH 터널은 이 재생에 사용하지 않습니다.
서버 측 측정 결과는 2단계 명령이 저장하며 Mac 재생은 시각 확인용입니다.
다른 폴더로 만들었다면 복사 명령의 서버 경로도 해당 폴더로 바꿉니다.

큰 정보 박스와 그래프는 추가하지 않았습니다. 도로·차로·자동차·기본 신호 표시를 확인합니다.
마우스로 확대·이동하고 상단 Delay로 속도를 조정할 수 있습니다.
이 시나리오에는 아직 DQN이 연결되지 않았으며 기존 toy 모델도 사용하지 않습니다.

## 입력 가정

| 항목 | 현재 설정 |
|---|---|
| 원본 | OSM 도로 형상·진행 방향·기록된 차로 수 |
| 도로 범위 | 광나루로 연결부, 화양삼거리 북·남측, 어린이대공원역 북·남측 접근부 |
| 차로 수 누락 | 일방통행 간선 2차로, 양방향 지선 합계 2차로 |
| 속도 | 간선 50km/h, 지선 30km/h를 실험상 적용 |
| 서·동측 유입 | 각각 600대/시간 |
| 화양 북·남측 유입 | 각각 180·90대/시간 |
| 어린이대공원 북·남측 유입 | 각각 450대/시간 |
| 출발 | 시드로 고정한 지수분포 도착 간격, 0–1080초 |
| 에피소드 | 0–1200초, Warm-up 120초, 1초 간격 |
| 수정한 고정신호 | 한 진입 방향씩 녹색 30초·황색 3초·전적색 3초. 다른 방향은 적색 |
| Offset | 화양 0초, 어린이대공원 15초 가정 |

위 숫자는 실측값이 아닙니다. 실제 생성된 현시 수·색상·주기는 `network_inventory.json`에 기록됩니다.
보행·버스 정류장·선택하지 않은 골목과 OSM 회전 규제 relation은 현재 부분망에 포함하지 않습니다.
도로 양끝은 원본 노드에서 잘라 양방향 경계 위치가 조금 다를 수 있습니다.
OD 가중치는 설정 파일에 있으며, 도달 불가능한 OD는 누락 목록과 재정규화 비율을 기록합니다.
각 경계의 총 차량 유입률을 줄여서 연결 실패를 숨기지 않습니다.

## 주요 파일과 다음 완료 조건

설정은 `configs/sejong2.json`, 생성 코드는 `scripts/build_sejong2.py`,
측정 코드는 `scripts/run_sejong2_fixed.py`입니다.
성공 시 `sumo/sejong2_v2/`에 다음 파일이 생깁니다.

| 파일 | 내용 |
|---|---|
| `sejong.net.xml`, `sejong.rou.xml` | 도로망과 고정된 차량 경로·출발 목록 |
| `sejong.sumocfg`, `sejong.gui.sumocfg` | 서버 측정 / Mac 시각 확인용 설정 |
| `assumptions.json` | 원본 태그와 대체한 가정값, 제외 범위 |
| `network_inventory.json` | 신호별 진입 차로·현시·주기·연결, 경계 목록 |
| `signal_plan_audit.json` | 한 방향씩 녹색, 연결 충돌·합류, 신호 제공과 전환 단계 검사 |
| `demand.json` | OD 경로, 실제 차량 수, 도달 불가능 OD |
| `manifest.json` | 원본·입력 해시, 변환 명령과 생성 상태 |

현재 수정본은 생성·집계·안전 검사를 통과했고 정체는 일부 남았습니다.
세종대 사례에 DQN을 확장하는 일은 선택 사항으로 두며, 다음 필수 작업은 가상 도로망의 중앙집중형 DQN 실험입니다.

사용자가 실행하는 오프라인 검사:

```bash
.venv/bin/python -m unittest discover -s tests -v
```
