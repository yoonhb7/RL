# 첫 Fixed-time 실행 기록

작업일: 2026-11-08 (Asia/Seoul)

## 완료 범위

계획서의 0단계와 1단계 중 **환경 설치, 가상 교차로 생성, TraCI 연결,
고정신호 실행 및 지표 산출**을 완료했습니다.
현재 설정은 계획서에 제안된 단순 연습용 설정입니다.
논문 실험 수치의 재현이나 세종대 현장 자료의 재현을 의미하지 않습니다.
DQN은 아직 구현하지 않았습니다.

## 환경 및 입력

- Python 3.10.12, Linux x86_64.
- eclipse-sumo, sumo-data, traci, sumolib 모두 1.28.0.
- 설치 위치: 프로젝트 내부 `.venv`.
- 환경 확인 기록: `results/environment/versions.json`.
- 방향별 1차로, 직진 전용, 진입/유출 도로 각각 250m.
- 녹색 30초, 황색 3초, 전적색 1초, 두 방향 합계 주기 68초.
- 수요 시드 42, SUMO 시드 42.
- 0–1080초에 출발 예정인 차량 433대. 실행 종료는 1200초.
- 분석 차량 집단: 출발 예정시각이 120초 이상, 1200초 미만인 차량 377대.
- 매초 대기행렬 측정 구간: `(120, 1200]`.

|---|---:|
| 북 | 133 |
| 남 | 121 |
| 동 | 79 |

단일 가상 수요 시드의 동작 확인 결과로, 정책 성능의 일반화나 통계적 우위를 뜻하지 않습니다.

## 검증 결과

1. `tests/test_baseline.py`의 회귀 검사 7개 통과.
2. `results/fixed/repeat_seed_42/`에 같은 수요와 시드로 다시 실행.
   차량 집계, 모든 지표, 안전 검사, 신호 변경 횟수, 입력 해시가 일치했습니다.
   `queues.csv`도 바이트 단위로 일치했습니다.
3. `results/fixed/truncated_seed_42/`에서 180초 종료 조건으로 실행.
   전체 수요 433대가 **도착 60 + 미완료 23 + 향후 출발 예정 350**으로 일치했습니다.
   이 실행의 분석 집단 27대 중 5대만 도착했고 22대가 미완료였습니다.
   완료 차량만의 평균 대기시간은 0초였지만 미완료를 포함한 관측 평균은 2.9630초였습니다.
   어느 쪽도 미완료 차량의 최종 대기시간을 뜻하지 않으므로 기본 실행과 직접 성능 비교하지 않습니다.
4. 각 실행에서 매초 누적 출발/도착 수를 TripInfo와 비교하고,
   마지막 TraCI 활성 차량 수가 미완료 수와 일치하는지 검사했습니다.

## 구현 중 확인한 사항

- 기본 실행 샌드박스에서 외부 다운로드 및 로컬 TCP 소켓 생성이 제한되었습니다.
  권한을 허용한 실행에서 패키지를 설치하고 TraCI 시뮬레이션을 검증했습니다.
- SUMO의 신호 연결 인덱스는 `.tll.xml`에서 명시해야 합니다.
  생성된 `.net.xml`의 실제 차로 연결을 다시 검사하도록 했습니다.
- 초기 실패 실행의 `results/fixed/seed_42/`, `baseline_seed_42/`는 정상 결과가 아닙니다.
  유효한 기본 결과는 `validated_seed_42/metrics.json`입니다.
- `sumo-gui --version`은 확인했으며 GUI 창을 열거나 시연 영상을 촬영하지는 않았습니다.
- 생성물 `results/`, `.venv/`, `.tools/`는 Git에서 제외했습니다.
  재현 코드, 생성 입력, 생성된 toy 도로망·경로, 본 기록은 저장소에 포함할 수 있습니다.
