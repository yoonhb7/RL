# 도시형 SUMO 화면

변경일: 2026-11-14. 기존 SUMO 창을 닫고 `START_VIEW.cmd`를 다시 열면 새 화면을 사용한다.

## 표시 개선

- 자동차: 차체, 유리창, 지붕, 바퀴, 전조등·후미등을 구분한다. 네 방향의 원래 차량 색상을 유지한다.
- 실제 SUMO 차량에 `polygon.addDynamics`로 도형을 부착하므로 차량의 위치·우회전 각도를 그대로 따라간다.
- 큰 3색 신호등 4개: SUMO의 실제 신호 문자열을 읽어 빨강·노랑·초록을 연동한다. 신호등 모양은 보기 쉽게 확대했다.
- 도시 주변: 건물·옥상 설비·그림자·보도·연석·주차장·가로수·작은 공원·분수·벤치.
- 도로 표시: 회색 아스팔트, 중앙선, 진행 화살표, 정지선, 횡단보도 도색.
- 청록색 검지 영역은 화면에서 가리고, 실제 E2 검지와 13개 관측값은 그대로 사용한다.

이 장식은 그래픽이다. 보행자, 추가 차로, 차량, 장애물, 신호 제어 규칙을 실험에 추가하지 않는다. 주차장 차들은 장식 도형이며 교통량이나 처리량에 포함되지 않는다. 횡단보도도 표시만 추가했으며 보행자 신호 제어 실험을 의미하지 않는다.

## 검증

1. 같은 차량 파일·시드·고정 제어로 190초를 실행했다. GUI 장식 유무에 대해 차량 파일 해시·예정/진입/도착/잔여/미진입·정지시간·미진입 대기·체류·배출·보상·전환·방향별 정지시간 등 13개 결과가 동일했다. `results/city-physics-check.json` 참조.
2. 네 방향 신호 도형의 색을 SUMO 내부 폴리곤에서 다시 읽어 `GGrrGGrr`, `yyrryyrr`, `rrGGrrGG`, `rryyrryy` 상태와 일치함을 확인했다.
3. 자동차 외곽 도형 140개(차량별 내/외곽 포함)의 실제 SUMO 폴리곤 좌표를 차량 위치·각도로 계산한 좌표와 대조했다. 최대 차이는 부동소수점 반올림 수준이었다. `results/city-tracking-check.json` 참조.
4. 기존 분석·학습·SUMO 통합 검사 8개 통과. 학습된 고교통량 Double DQN GUI 실행도 종료까지 확인했다.

## 미리보기와 코드 기록

`simulation.svg`와 `simulation.png`는 180초의 실제 차량 좌표·신호·장면 폴리곤으로 저장한 벡터 미리보기다. 네이티브 GUI 화면의 픽셀 캡처와 구분한다. 이 컴퓨터에서 복잡한 장면의 OpenGL 화면 읽기가 대기하는 현상이 있어 일반 실행에서는 네이티브 캡처를 끄고 벡터 장면 저장을 사용한다.

표시 코드는 `trafficbench/appearance.py`, 연결 지점은 `env.py`의 GUI 조건부다. 도로 네트워크·모델 구조·보상·수요 설정 및 기존 체크포인트는 바꾸지 않았다. 표시 코드 변경도 코드 해시에 포함되므로 미래 실험용 작업표를 새로 생성했다. 이전 파일럿 `results/pilot-v2`와 그 결과표는 당시 기록으로 보존하고, 새 파일럿은 `results/pilot-v3`에 저장한다. 기존 모델을 이 화면에서 보는 데 재학습은 필요 없다.

새 파일럿의 기준선까지 다시 만들려면 다음을 실행한다.

```text
python start.py --config configs/pilot.json calibrate --out results/pilot-baselines-v3
```
