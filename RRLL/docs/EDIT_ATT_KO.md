# EDIT_ATT: 진입 대기를 포함한 고정 차량 집단의 ATT

이 브랜치는 `RRLL`의 21차원 상태, 4현시, 세 DQN 모델, 보상, 200에피소드 및 학습 시드 설정을 유지하고 ATT 평가를 수정한다.

## ATT 정의

- 대상: 출발 예정 시각이 0초 이상 3,600초 미만인 **모든** 차량.
- 차량별 시간: **실제 도착 시각 − 출발 예정 시각**.
- ATT: 위 차량별 시간을 대상 차량 전체에 대해 평균한 값. 도로 진입을 기다린 시간도 포함한다.
- 이는 진입 이후 시간만 사용하는 지표와 구별되는 본 연구의 평가 정의다. 원 논문들의 ATT와 수치를 직접 비교하려면 정의를 맞춰야 한다.

예정 출발 100초, 실제 진입 140초, 도착 220초인 차량의 ATT 기여는 120초다. 진입 후 주행시간 80초만 계산하지 않는다.

## 평가 실행

1. 기존 해시 고정 수요 파일을 읽고 평가 출력 폴더에 복사한다. 복사본에서 3,600초 이후 출발 예정 차량을 제외한다. 원본은 수정하지 않는다.
2. 기존 정책으로 3,600초를 실행한다. 이 시점의 대기열, AQL, 도착·미완료·진입 대기 차량 수와 보상은 그대로 기록한다.
3. 새 차량 수요는 추가하지 않고, 대상 차량이 **모두 진입하고 도착할 때까지** 같은 정책을 탐욕적으로 실행한다. 이 구간에는 리플레이 저장이나 신경망 업데이트가 없다.
4. 모든 차량의 완전한 통행시간으로 검증 ATT를 계산하고, 저·중·고 수준의 평균을 같은 비중으로 모델 선정에 사용한다.
5. 추가 실행의 상한은 `evaluation_max_drain_seconds=14400`(시뮬레이션 시간 4시간)이다. 상한까지 완료하지 못하거나 충돌이 발생하면 해당 검증은 실패로 기록하며, 차량을 빼고 평균하거나 낮은 점수로 처리하지 않는다. 이 상한은 정체를 버리기 위한 기준이 아니라 무한 실행 방지용이다.

`counts`와 `AQL_in_vehicles`는 **원래 1시간 구간**의 값이다. `drain.arrived`와 `drain.seconds`는 추가 실행 완료 결과다. 두 구간을 혼합하지 않는다.

## 학습 로그와 평가 점수 구분

학습은 여전히 3,600초/240결정에서 끝나고 마지막 실제 상태에서 부트스트랩한다. 학습 에피소드마다 모든 차량을 통과시키는 추가 실행은 하지 않는다.

- `ATT_s`: 모든 대상 차량이 도착한 경우에만 존재하는 완전한 ATT. 검증 모델 선정은 이 값만 사용한다.
- `ATT_observed_due_s`: 학습 진단값. 도착 차량은 도착 시각까지, 미도착·미진입 차량은 3,600초까지의 경과시간을 예정 출발 시각에서 계산하고 모든 대상 차량에 대해 평균한다. 완전한 ATT가 아니며 검증 점수와 직접 비교하지 않는다.
- `ATT_entered_tripinfo_s`: tripinfo에 기록된 진입 차량의 평균 주행시간. 진입 대기가 빠져 있으므로 진단용으로만 보존한다.
- `AWT_s`: 완전한 평가 집단의 정지 대기시간에 진입 전 대기를 더한 평균. 학습 중 미완료 집단은 `AWT_observed_due_s`로 별도 표시한다.
- `ATT_protocol.name`: `scheduled_departure_to_arrival_all_due_v1`. 과거 프로토콜의 결과를 새 모델 선정에 섞지 않는다.

## 실행

저장소에서 `RRLL` 폴더로 이동하고 기존 실행 환경을 활성화한다.

```bash
python -m unittest discover -s tests -p "test_fourphase*.py"
python scripts/check_att.py
python scripts/train_all_seeds.py
```

`check_att.py`는 학습하지 않은 고정 행동 정책으로 실제 SUMO에서 ATT 처리만 확인한다. 알고리즘 성능 비교 결과가 아니다.

학습 한 번만 실행하려면:

```bash
python scripts/train_fourphase_dqn.py --algorithm double_dqn --seed 42 --output results/fourphase_dqn_EDIT_ATT/double_dqn_seed42
```

전체 학습 결과는 기본적으로 `results/fourphase_dqn_EDIT_ATT/`에 저장하여 이전 ATT 결과와 구분한다. `--output-root`로 새 경로를 지정할 수도 있다. 스크립트는 결과 폴더가 이미 있으면 건너뛰므로, 이 브랜치에서 실패·중단한 실행을 다시 돌릴 때도 미완료 폴더를 완료된 실행으로 혼동하지 않도록 확인하고 새 출력 경로를 사용한다.

추가 실행 때문에 검증 소요 시간은 기존 문서의 추정치보다 늘어날 수 있다. 독립 테스트·Fixed-time 평가의 추가는 이 ATT 수정과 별도 작업이다.

## 2026-11-17 실행 검증

- 회귀 테스트 36개 통과.
- 실제 SUMO 1.28.0의 저·중·고 수요에서 각각 1,168 / 1,766 / 2,387대 모두 도착. 1시간 이후 추가 실행은 각각 240 / 240 / 465초. 차량 보존·보상·시간 구간 검증 통과.
- 진입 지연 스트레스 사례: 한 차로에 출발 예정 차량 800대를 배치. 3,600초 시점에 344대가 진입 전 대기 중이었지만, 추가 실행 후 800대 모두 도착했고 ATT에 전부 포함됨.
- Double DQN 6에피소드 / 1,440결정 / 440업데이트 완료. 검증 수요 9개를 모두 실행하고 새 ATT 기준으로 `best_model.pt` 및 학습 그래프 저장까지 확인.
- 3종 × 5시드 × 200에피소드 본실험은 이 검증에서 실행하지 않았으며, 위 수치는 학습 성능의 우열을 나타내지 않음.

검증 런타임은 Python 3.12.14, PyTorch 2.15.0, NumPy 2.5.4, Gymnasium 1.2.2다. 설치 안내의 고정 버전 환경과는 구분한다. 간략한 실행 근거는 [EDIT_ATT_CHECKS.json](EDIT_ATT_CHECKS.json)에 보존한다.
